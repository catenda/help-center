# Onglet Aperçu dans une demande de validation

L'onglet Aperçu d'une demande de validation se trouve sur la page de demande de validation des approbations [ouvertes ou fermées](https://support.catenda.com/en/articles/12494960-open-or-closed-approval-request-page). Dans l'onglet Aperçu, vous pouvez voir un aperçu d'une étape d'examen de validation sélectionnée. À cette étape, les validations indiquées et soumises par un membre au nom de chaque équipe de soumetteur configurée pour examiner l'étape peuvent être vues. Pour un aperçu des soumissions de validations pour toutes les étapes, consultez l'[onglet Documents](https://support.catenda.com/en/articles/8349418-approval-page#h_133b2690af).

> **Remarque :** **Apparence -** Voici à quoi peut ressembler l'onglet Aperçu dans le contenu de validation pour les projets qui ont activé les révisions partagées après le 2 octobre 2025 :

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/01-intro.png)

## 1. Ruban d'étape de demande de validation

Dans le ruban d'étape, un aperçu de la progression de la demande de validation peut être vu. Voici à quoi peut ressembler le ruban d'étape :

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/02-approval-request-step-ribbon.png)

Cliquez [ici](https://support.catenda.com/en/articles/12495212-step-ribbon-in-an-approval-request) pour en savoir plus sur le ruban d'étape

## 2. Menu déroulant d'étape de validation

Voici à quoi peut ressembler le menu déroulant d'étape de validation lorsqu'une demande de validation a atteint l'étape de validation finale :

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/03-approval-step-dropdown.png)

Les étapes de validation actuelles et toutes les étapes passées sont listées dans le menu déroulant d'étape de validation. Sélectionnez une étape de validation dans la liste pour voir le statut des validations données par chacune des équipes configurées pour l'étape. Un aperçu des validations dans toutes les étapes peut être trouvé dans l'onglet Documents.

## 3. Tableau En cours d'examen

Dans le tableau En cours d'examen, les documents qui n'ont pas encore été soumis peuvent être vus. Voici à quoi peut ressembler le tableau En cours d'examen :

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/04-under-review-table.png)

Les membres qui font partie des équipes configurées en tant qu'équipes d'examinateurs pour cette étape de demande de validation verront une ligne par équipe d'examinateur configurée dont ils font partie. À l'étape active de demande de validation, s'il y a encore des indications de validation à soumettre au nom de toute équipe d'examinateur dont un membre fait partie, une barre jaune est affichée vers le haut.

Lorsque tous les documents ont été examinés et que les indications de validation ont été soumises au nom de chacune des équipes d'examinateurs, la barre vers le haut devient verte et reçoit une coche.

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/05-under-review-table.png)

> **Remarque :** La barre étant verte signifie simplement qu'il n'y a pas d'équipes dont vous faites partie qui ont des actions restantes à effectuer dans cette étape de demande de validation. Il peut y avoir d'autres équipes qui doivent encore soumettre leurs indications de validation avant que la demande de validation puisse passer à l'étape suivante. Ceux-ci peuvent être vus dans le tableau Aperçu des étapes ci-dessous.

### 3.1 Colonnes du tableau En cours d'examen

**Équipe** Noms des équipes d'examinateurs configurées pour cette étape de validation dans le flux de validation sélectionné pour cette demande de validation par l'émetteur de la demande de validation. _Accès requis :_ Membre de l'équipe d'examinateurs

**En attente** Le nombre de documents qui n'ont pas encore reçu d'indication de validation dans cette étape de demande de validation. _Accès requis :_ Membre de l'équipe d'examinateurs Examiner Cliquez sur Examiner pour ouvrir l'examen des fichiers pour les documents qui n'ont pas encore reçu d'indication de validation ou de soumission au nom d'une équipe d'examinateurs dans cette étape de demande de validation.

**Examiné** Dans la colonne Examiné, les montants des indications de validation rejetées et approuvées sont affichés. Tout membre d'une équipe d'examinateurs peut avoir donné cette indication au nom de l'équipe d'examinateurs. _Accès requis :_ Membre de l'équipe d'examinateurs Soumettre Les indications de validation que les membres de l'équipe d'examinateurs ont données au nom d'une équipe d'examinateurs peuvent être soumises avec le bouton Soumettre. Cliquez sur le bouton Soumettre pour soumettre toutes les indications de validation au nom de l'équipe d'examinateurs à la fois. Une fois que l'indication de validation est soumise, le document ne sera plus en cours d'examen et disparaîtra du tableau En cours d'examen.

## 4. Tableau Aperçu des étapes

Dans le tableau Aperçu des étapes, un aperçu de la progression de tous les équipes d'examinateurs pour cette étape peut être vu.

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/06-step-overview-table.png)

Lorsque les indications de validation sont soumises pour tous les documents, la demande de validation passe à l'étape de demande de validation suivante. L'approbation automatique peut être configurée dans le flux que l'émetteur de la demande de validation a sélectionné pour cette demande de validation. Si l'approbation automatique est activée pour une étape de demande de validation, tous les documents qui sont toujours en attente lorsque l'étape de demande de validation est due sont approuvés automatiquement et la demande de validation passe à l'étape de demande de validation suivante.

### 4.1 Colonnes du tableau Aperçu des étapes

**_Équipe_ —** Noms des équipes d'examinateurs configurées pour cette étape de validation dans le flux sélectionné pour cette demande de validation.

**_En attente_ —** Le nombre de documents pour lesquels un membre de l'équipe d'examinateurs n'a pas encore soumis d'indication de validation au nom de l'équipe d'examinateurs dans cette étape de demande de validation.

**_En cours d'examen –_** _Le nombre de documents qui sont Approuvés ou rejetés mais pas encore soumis. Lorsqu'ils ne sont pas soumis mais disponibles pour soumission, le bouton « soumettre » est vert foncé._

**_Soumis_ —** Le nombre d'indications approuvées qui ont été soumises par un membre de l'équipe d'examinateurs au nom d'une équipe d'examinateurs dans cette étape de demande de validation.

**_Progression de l'équipe_ —** La progression des indications de validation qui ont été soumises par un membre de l'équipe d'examinateurs au nom d'une équipe d'examinateurs dans cette étape de demande de validation.

Après que l'équipe d'approbateur final soumet la validation finale pour tous les documents, la demande de validation est fermée et les documents commencent à être publiés :

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/07-approval-request-result.png)

Le résultat de la validation est affiché sous l'aperçu des étapes :

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/08-approval-request-result.png)

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/09-approval-request-result.png)

Cliquez [ici](https://support.catenda.com/en/articles/12520773-approvals-troubleshooting) pour en savoir plus sur les raisons pour lesquelles la publication des documents peut échouer.

### 5.1 Voir les détails

Cliquez sur Voir les détails pour voir les résultats de publication pour chaque document.

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/10-view-details.png)

**Statut**

![](https://raw.githubusercontent.com/catenda/help-center/main/images/0se83h1m/11-view-details.png)

Le statut de la publication du document. Le statut peut être l'un des suivants :

**Publié** Pour les documents qui ont reçu une approbation finale, le numéro de révision de la révision partagée est affiché avec une flèche vers la révision publiée qui a été créée à la suite de la publication de cette révision partagée.

**Échec de la publication** Pour les documents qui ont reçu une approbation finale mais qui n'ont pas pu être publiés, la raison pour laquelle ils n'ont pas pu être publiés est affichée.

**Définir le statut** Pour les documents qui ont reçu un rejet final, le statut avec lequel la révision a été mise à jour en conséquence est affiché.

**_Nom_** Les éléments suivants sont affichés dans la colonne Nom :

- Chemin du fichier du document
- Icône du document
- Nom de la révision du document
