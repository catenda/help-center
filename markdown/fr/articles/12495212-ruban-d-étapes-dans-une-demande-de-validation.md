# Ruban d'étapes dans une demande de validation

Le ruban d'étapes se trouve en haut d'une page de demande de validation [brouillon](https://support.catenda.com/en/articles/12495175-draft-approval-request-page), [ouvert ou fermé](https://support.catenda.com/en/articles/12494960-open-or-closed-approval-request-page) pour les projets ayant activé les révisions partagées après le 2 octobre 2025. Dans le ruban d'étapes, un aperçu de toutes les étapes de révision de validation dans une validation s'affiche. Voici à quoi le ruban d'étapes de la demande de validation peut ressembler pour une demande de validation où un flux de travail de validation est sélectionné avec le nombre maximum d'étapes de demande de validation :

![Ruban d'étapes d'approbation. Étape 2 Échéance Approbation finale 10 étapes](https://raw.githubusercontent.com/catenda/help-center/main/images/1bshvqk0/01-intro.png)

Les projets pour lesquels les révisions partagées ont été activées avant le 2 octobre 2025 verront plutôt la page de demande de validation hérité.

## 1. **Étape de demande de validation créée**

Survolez l'étape créée pour voir les informations sur la création de la demande de validation. Consultez le nom du membre qui a créé la demande de validation. Au moment de la création, le membre doit avoir fait partie d'une équipe de soumissionnaire configurée pour ce flux de travail de validation. Consultez quand la demande de validation a été créée.

![Demande de ruban d'approbation survol de l'étape créée par nom d'utilisateur échéance](https://raw.githubusercontent.com/catenda/help-center/main/images/1bshvqk0/02-created-approval-request-step.png)

### 1.1 **Étape créée dans une demande de validation brouillon**

Voici à quoi l'étape créée peut ressembler dans une demande de validation brouillon :

![Ruban d'approbation étape créée date rouge en retard vérification d'approbation finale](https://raw.githubusercontent.com/catenda/help-center/main/images/1bshvqk0/03-created-step-in-draft-approval-request.png)

Les validations brouillon réussissent leur date de création dès leur création. La date de création apparaît donc toujours en rouge.

## 2. **Étape de demande de validation réussie**

Survolez une étape de validation réussie pour voir les informations sur l'étape de demande de validation réussie. Consultez l'échéance de l'étape de demande de validation réussie. Quand l'échéance a dépassé, elle apparaîtra en rouge. Consultez les équipes configurées pour cette étape de validation.

![Étape de demande en retard ruban d'approbation survol échéance en rouge équipes à examiner mentionnées](https://raw.githubusercontent.com/catenda/help-center/main/images/1bshvqk0/04-passed-approval-request-step.png)

## 3. **Étape de demande de validation actuelle**

Quand une étape de demande de validation est l'étape actuelle, l'échéance de l'étape de validation actuelle peut être vue dans l'aperçu de l'étape de demande de validation. Quand l'échéance a dépassé, elle apparaîtra en rouge. Survolez l'étape de demande de validation actuelle pour voir les informations sur l'étape de demande de validation actuelle.

![Ruban d'approbation étape d'examen survol avec 10 équipes d'examen toutes listées dans la fenêtre contextuelle](https://raw.githubusercontent.com/catenda/help-center/main/images/1bshvqk0/05-current-approval-request-step.png)

Avance automatique activée - La demande de validation se déplacera automatiquement vers l'étape suivante après l'échéance Avance automatique désactivée - La demande de validation reste à l'étape après avoir dépassé l'échéance et n'avancera que si tous les relecteurs ont soumis leur révision de validation. Consultez les équipes de relecteurs configurées pour cette étape de demande de validation.

## 4. **Étape de demande de validation future**

Survolez une étape de validation future pour voir les informations sur l'étape de validation future.

![Ruban étape de demande d'approbation étape d'examen survol avec une équipe à examiner pas encore due](https://raw.githubusercontent.com/catenda/help-center/main/images/1bshvqk0/06-future-approval-request-step.png)

Consultez les équipes de relecteurs configurées pour cette étape de demande de validation. Les étapes futures n'ont pas encore d'échéance car le nombre de jours ouvrables pour compléter l'étape commencera dès que l'étape précédente sera terminée.

## 5. Étape de validation finale

Quand l'étape de validation finale est l'étape actuelle, l'échéance de l'étape de validation finale peut être vue dans l'aperçu de l'étape. Quand l'échéance a dépassé, elle apparaîtra en rouge. Les étapes de validation finale futures n'ont pas encore d'échéance car le nombre de jours ouvrables pour compléter l'étape commencera dès que l'étape précédente sera terminée. Survolez l'étape de demande de validation actuelle pour voir les informations sur l'étape de demande de validation actuelle.

![Demande d'approbation étape d'approbation finale survol avec équipe d'examen finale listée dans la fenêtre contextuelle](https://raw.githubusercontent.com/catenda/help-center/main/images/1bshvqk0/07-final-approval-step.png)

Consultez l'équipe approbatrice configurée pour l'étape de validation finale. Un membre de l'équipe approbatrice finale peut prendre la décision de validation finale concernant l'approbation ou le rejet des documents dans cette demande de validation en fonction des décisions de validation prises par chacune des équipes de chacune des étapes. Quand le membre qui valide a soumis sa validation comme approuvée ou rejetée pour chacun des documents, le flux de travail de validation sera fermé. Une approbation finale doit toujours être soumise pour fermer une demande de validation. Il n'y a pas d'avance automatique pour l'étape de validation finale.

Quand toutes les validations finales sont soumises, la demande de validation sera fermée.

![Ruban étape de demande d'approbation approbation finale étape fermée en vert avec date de fermeture](https://raw.githubusercontent.com/catenda/help-center/main/images/1bshvqk0/08-final-approval-step.png)

L'étape de demande de validation finale obtient alors un arrière-plan vert. La date à laquelle toutes les validations finales ont été soumises s'affiche.
