# About Catenda AI Connect for Microsoft Copilot

> Catenda AI Connect brings Catenda Hub project data into Microsoft 365 Copilot and Teams through an agent. What teams use it for, what an organization sets up and how to get started.

> **Important:** Catenda AI Connect is in early access. Features and setup steps change often, so what appears on screen can differ from this article.

> **Note:** This article is for signed-out readers. Links to all three levels of this topic are at the end of this article.

Many project teams already work in Microsoft 365, with Copilot and Teams open all day. Catenda AI Connect brings the models, documents and topics in Catenda Hub into that same place. Questions about a project are asked in plain language in Microsoft 365 Copilot or Teams, and answered from the live project data.

## 1. **What it is**

In Microsoft 365, Catenda AI Connect reaches users through an agent. The organization builds this agent once in Copilot Studio, approves it, and makes it available in Microsoft 365 Copilot, Teams or both. Team members then find the agent with the Catenda connector among the other agents their organization provides.

This is what such an agent, here named Catenda, can look like among the agents in Microsoft 365 Copilot:

![The Agents menu in Microsoft 365 Copilot with the agent named Catenda](https://catenda.github.io/help-center-ops/images/dvhm7pka/01-what-it-is.png)

The connection uses MCP (the Model Context Protocol), an open standard for connecting AI apps to other systems. [About Catenda AI Connect](https://support.catenda.com/en/articles/17778695-about-catenda-ai-connect) describes the product as a whole.

## 2. **What teams use it for**

### 2.1 **Ask**

Questions are answered from the live project data, with sources, right inside a Teams or Copilot chat. For example:

```
What is overdue on the project, and who is it assigned to?
```

### 2.2 **Check**

Topics, models and documents are checked against the project's requirements. They can relate to deliveries or any other task. For example:

```
Check the latest delivery against our naming rules and list what fails.
```

### 2.3 **Delegate**

Structured busywork is done as drafts a person approves, where the organization allows the agent to make changes. For example:

```
Create a topic for each action item in these meeting minutes.
```

## 3. **What the organization sets up**

Agents with the Catenda connector are set up centrally, by two people with different roles. An organization can set up more than one, each allowed to do different things in Catenda Hub and available to different people.

### 3.1 **Requirements**

The organization needs a Microsoft 365 Business or Enterprise subscription. The person who builds the agent also needs a Copilot Studio license or trial. Using the agent needs neither of these extra licenses. The subscription and the Copilot Studio license are bought from Microsoft, in the Microsoft 365 admin center under **Billing** > **Purchase services**, or through a Microsoft partner.

### 3.2 **Agent builder**

An agent builder creates the agent in Copilot Studio, adds the Catenda connector to it and submits it to the organization's catalog. The Catenda connection arrives in Copilot Studio as a custom connector, so the organization's data policies need to allow custom connectors. In Power Apps, that connector is then shared with the people approved to use the agent: specific users, a group or the whole organization. The agent can run on the organization's choice of language model, including Anthropic models where the organization turns them on.

This is what the Agents page in Copilot Studio can look like:

![The Agents page in Copilot Studio with the New agent button](https://catenda.github.io/help-center-ops/images/dvhm7pka/01-agent-builder.png)

### 3.3 **Microsoft 365 administrator**

A Microsoft 365 administrator approves the agent before anyone sees it. The administrator also decides who can install it: everybody in the organization, or only specific teams. Another team can be given the agent later, without building it again.

## 4. **Control over project data**

Each team member signs in with their own Catenda account the first time they use the agent. The agent then works with exactly the access that person has in Catenda Hub, and the project's permissions apply unchanged.

The organization decides which kinds of actions the agent may take, such as reading project data, creating topics or changing them. Access can be set per feature, for example so the agent may create topics but only reads everything else. It can also have the agent ask the user before each action, so a person stays in control of what is written.

## 5. **Getting started**

Catenda AI Connect is available in early access.

Catenda AI Connect is not only for organizations that own projects in Catenda Hub. An organization that is invited to the projects of other organizations can get Catenda AI Connect too. Such an organization does not need to own a project itself. Catenda AI Connect then works on two kinds of project. The first kind is the projects the organization runs itself. The second kind is the projects the organization is invited to, as long as the organization running that project allows Catenda AI Connect there. When an organization allows Catenda AI Connect on a project, that does not mean every invited person can use Catenda AI Connect there. Each person's own organization may have a policy against using AI on projects. [Catenda AI Connect and project access](https://support.catenda.com/en/articles/17778745-catenda-ai-connect-and-project-access) describes this in more detail.
