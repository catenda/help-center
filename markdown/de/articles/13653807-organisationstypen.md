# Organisationstypen

Für einen Kunden können beliebig viele Organisationen erstellt werden, aber je nach Organisationstyp können sie verschiedene Arten von Projekten enthalten.

## 1. **1. Aktive Projektorganisation**

Ein laufendes Bauprojekt kann Teil einer aktiven Projektorganisation sein. Für jede Organisation kann ein Plan konfiguriert werden. Diejenigen, die für die Verwaltung von Catenda innerhalb einer Organisation verantwortlich sind, können als Eigentümer der Organisation festgelegt werden. Organisationseigentümer können durch Konfigurieren eines Plans mit einer Projektbegrenzung für die Organisation Zugriff auf die Projekterstellung erhalten. Die folgenden Enterprise-Pläne sind verfügbar:

### 1.1 **1.1 Maximale Projektanzahl**

Mit diesem Plan können zu einem bestimmten Zeitpunkt bis zu einer festgelegten Anzahl von Projekten vorhanden sein.

### 1.2 **1.2 Organisation nach Projektgröße**

Die Arten von Projekten in dieser Organisation hängen von der Größe jedes einzelnen Projekts ab. Ähnlich große Projekte werden in derselben Organisation zusammengefasst.

### 1.3 **1.3 Unbegrenzte Projekte**

In dieser Art von Organisation kann eine beliebige Anzahl von Projekten erstellt werden. Aus Sicherheitsgründen wird für diese Art von Organisationen häufig eine Projektbegrenzung gesetzt, die höher ist als wahrscheinlich erreichbar.

### 1.4 **1.4 Bildungseinrichtungen**

Projekte von Studierenden aus jüngsten Bildungsperioden werden häufig in diesen Arten von Organisationen aufbewahrt.

**Verfallsdatum** Ein Verfallsdatum wird häufig für die Organisation konfiguriert, sodass Projekte, die in dieser Organisation erstellt werden, nach einer bestimmten Zeit ablaufen. Wenn ein Verfallsdatum für eine Bildungsorganisation festgelegt ist, wird es häufig auf 365 Tage nach der Projekterstellung gesetzt. Das für die Organisation konfigurierte Verfallsdatum gilt nur für neue Projekte, die in der Organisation erstellt werden. Das Verfallsdatum für bestehende Projekte kann nur von Catenda auf Projektebasis geändert werden.

> **Hinweis:** Dozenten können Projekte vor Beginn der Unterrichtsperiode vorbereiten, daher kann der Gesamtzeitraum, nachdem ein Studierender das Projekt erhält, kürzer sein.

## 2. **2. Inaktive Projektorganisation**

Übertragen Sie Projekte auf eine inaktive Projektorganisation, um einen Platz in der aktiven Projektorganisation freizugeben. Die Aktivität von Projektmitgliedern in diesen Arten von Projekten wird überwacht. Wenn mehr Projektaktivität von Mitgliedern festgestellt wird als erwartet für ein inaktives Projekt, wird das Projekt als aktives Projekt gezählt. Theoretisch ist es daher möglich, eine beliebige Anzahl von Mitgliedern in einem Projekt in dieser Art von Organisation zu haben, aber es wird empfohlen, die Mitgliederliste zu bereinigen. Das Organisationstool wird häufig verwendet, um alle Mitglieder bis auf die Hauptmitglieder zu entfernen, die für das Projekt und Organisationsadministratoren verantwortlich sind.

### 2.1 **2.1 Projekte in Wartestellung**

Ein typisches Projekt in dieser Organisation ist ein stillgelegtes Projekt. Projekte können aus vielen Gründen stillgelegt werden, zum Beispiel wenn ein Bauprojekt das Budget überschreitet oder wenn Ressourcen auf andere Projekte verteilt werden müssen.

### 2.2 **2.2 Nicht mehr in Gebrauch**

Andere Anwendungsfälle für diese Art von Organisation können Projekte umfassen, die nicht mehr in Gebrauch sind, die Menschen aber noch eine Zeit lang aufbewahren möchten. Ein Grund, ein Projekt in Catenda zu behalten, könnte sein, dass das Projekt beendet ist, aber noch keine Zeit vorhanden war, um alle Informationen zu exportieren, weil entweder die Zeit fehlte oder keine Archivierungslösung vorhanden ist.

**Archiv** Im Gegensatz zu anderen Lösungen, die speziell auf die langfristige Archivierung von Informationen ausgerichtet sind, ist Catenda für aktive Zusammenarbeit gedacht. In einigen Ländern ist es gesetzlich erforderlich, dass Catenda die Daten sofort nach Abschluss des Projekts löscht. In Situationen, in denen nicht erforderlich ist, dass das Projekt gelöscht wird, möchten Projekte möglicherweise länger aufbewahrt werden. Projekte werden dann häufig in eine Archivorganisation verschoben.

## 3. **3. Admin-Projektorganisation**

Eine Admin-Organisation wird erstellt, sobald das erste Testprojekt erstellt wird. Wenn ein Enterprise-Abkommen eingegeben wird, wird eine Admin-Organisation erstellt, falls noch keine vorhanden ist.

### 3.1 **3.1 Projekt mit neuen Funktionen**

Wenn zu irgendeinem Zeitpunkt der Customer Journey Fragen auftauchen, kann eine separate Organisation namens Admin erstellt werden, wenn diese noch nicht vorhanden ist. In der Organisation können Projekte erstellt werden, die nicht zur Gesamtzahl der aktiven Projekte zählen. Um die Fragen zu beantworten, kann ein Projekt in einer solchen Organisation erstellt werden, damit eine bestimmte Einrichtung oder Konfiguration ausprobiert oder neue Funktionen, die noch nicht für alle Benutzer verfügbar sind, aktiviert und in Betracht gezogen werden können.

**Verfallsdatum** Ein Verfallsdatum kann für die Dauer des Testzeitraums gesetzt werden, damit die Frage gelöst werden kann. Das Verfallsdatum kann nur von Catenda auf Projektebasis geändert werden.

### 3.2 **3.2 Vorlagenprojekt**

Jede Admin-Organisation enthält normalerweise ein Vorlagenprojekt. Nachdem die ersten wenigen Projekte einzeln konfiguriert wurden, wird oft ein Vorlagenprojekt in der Admin-Organisation von Catenda erstellt. In diesem Projekt werden typische Projektkonfigurationen erstellt, damit das Projekt als Vorlagenprojekt bei der Erstellung neuer Projekte verwendet werden kann. Typische Projektkonfigurationen können folgende Elemente enthalten: Benannte, leere Modelle auf der Modellseite. Topic Boards mit konfigurierten Einstellungen wie Status, Typen und benutzerdefinierten Feldern. Dokumentenseite mit Ordnerstruktur und Ordnerkonfiguration mit benutzerdefinierten Feldern und Namenskonvention. Die Zugriffskontrolle kann für alle diese Elemente konfiguriert werden, um in dem neuen Projekt verwendet zu werden. Projekteinstellungen wie benutzerdefinierte Felder und Namenskonventionen.

### 3.3 **3.3 Verwaltungsprojekte**

Verwaltungsprojekte werden häufig in dieser Organisation für interne Kommunikation und für die Diskussion über Gespräche mit Catenda erstellt. Diese Arten von Projekten haben normalerweise kein Verfallsdatum.

### 3.4 **3.4 Aktive Testprojekte**

Testprojekte werden häufig in dieser Organisation erstellt oder erneut geöffnet, solange sie nicht für echte Bauprojekte verwendet werden. Diese Projekte erhalten häufig ein Verfallsdatum, damit Catenda getestet werden kann, ohne das aktive Projekt zu beeinträchtigen.

### 3.5 **3.5 Inaktive Testprojekte**

Projekte, die in früheren Testphasen verwendet wurden, können häufig in dieser Organisation gefunden werden. Diese Projekte sind normalerweise Projekte wie: Bildungsprojekte, Testprojekte, Sandboxprojekte

**Verfallsdatum** Ein Verfallsdatum kann für die Dauer des Testzeitraums gesetzt werden, damit das Projekt aktiv bleibt, aber nicht mehr zugänglich ist. Das Verfallsdatum kann nur von Catenda auf Projektebasis geändert werden und wird oft von der Organisationskonfiguration geerbt, in der das Projekt erstellt wurde.

### 3.6 **3.6 Beispielprojekte**

Beispielprojekte können Projekte umfassen, die abgeschlossen und ordnungsgemäß konfiguriert wurden. Exemplarische Projekte werden häufig in die Admin-Organisation verschoben, um den Benutzern zu zeigen, wie ein echtes Projekt aussehen könnte.
