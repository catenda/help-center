# Status-Workflow - Dokumenteinstellungen

So kann das Status-Workflow-Menü auf der Seite [Dokumenteinstellungen](https://support.catenda.com/en/articles/7831371-document-settings-page) für Projekte aussehen, die gemeinsame Überarbeitungen nach dem 2. Oktober 2025 aktiviert haben. In neuen Projekten ist der Status-Workflow standardmäßig deaktiviert. So kann das Status-Workflow-Menü aussehen:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/g7ntz7r8/01-intro.png)

Projekte, die auf einem [Vorlagenprojekt](https://support.catenda.com/en/articles/4670245-creating-a-new-project#h_5db32e5398) basieren, und Projekte, die gemeinsame Überarbeitungen vor dem 2. Oktober 2025 aktiviert haben, werden das Menü des älteren Status-Workflows sehen.

## 1. **Gemeinsame Status**

Aktivieren Sie gemeinsame Status, um sich an ISO 19650 auszurichten und Workflows zu konfigurieren. So kann das Status-Workflow-Menü nach Aktivierung von gemeinsamen Status aussehen

![](https://raw.githubusercontent.com/catenda/help-center/main/images/g7ntz7r8/02-shared-statuses.png)

### 1.1 Aktivierung von gemeinsamen Status

Standardmäßig gibt es einen gemeinsamen Status mit dem Namen "Freigegeben", der konfiguriert ist. Typische Status, die hinzugefügt werden, sind:

- WIP - Blau
- In Bearbeitung - Blau
- Interne Validierung - Blau

**Projektänderungen**

- Informationen beginnen mit einer Nebenversionsnummer: 0.1, 0.2, 1.1, usw.
- Informationen können veröffentlicht werden, um eine Hauptversionsnummer zu erhalten: 1.0, 2.0, 3.0, usw.
- Das Zugriffssteuerungsmenü auf der Seite "Dokumente" verfügt über eine zusätzliche Spalte, in der der Zugriff auf gemeinsame Überarbeitungen und Veröffentlichungsrechte konfiguriert werden können.
- Gemeinsame und veröffentlichte Status - Neue Informationen werden in der gemeinsamen Phase eingereicht.
- Der Standardstatus ist auf "Freigegeben" festgelegt.
- Ein Genehmigungsmenü in den Dokumenteinstellungen wird angezeigt.
- Eine Genehmigungsunterseite zur Seite "Dokumente" wird angezeigt.

### 1.2 **Deaktivierung von gemeinsamen Status**

**Projektänderungen**

- Veröffentlichte Status - Neue Informationen werden in der veröffentlichten Phase eingereicht.
- Der Standardstatus ist auf "Kein Status" festgelegt.
- Das Genehmigungsmenü in den Dokumenteinstellungen ist deaktiviert.
- Die Genehmigungsunterseite zur Seite "Dokumente" ist deaktiviert.
  ​

## 2. **Veröffentlichte Status**

Standardmäßig gibt es einen veröffentlichten Status mit dem Namen "Veröffentlicht", der konfiguriert ist. Klicken Sie auf "Status hinzufügen", um weitere Status hinzuzufügen. Typische gemeinsame Status, die hinzugefügt werden, sind:

- Veröffentlicht mit Kommentaren - Hellgrün
- Wartend - Gelb
- Abgelehnt - Rot
  ​

## 3. **Status hinzufügen**

Sie können einen Status hinzufügen, indem Sie auf "Status hinzufügen" klicken. Ein neuer Status kann eine Farbe und einen Namen haben. Status können entweder zur Liste der gemeinsamen oder zur Liste der veröffentlichten Status hinzugefügt werden.

## 4. **Status ändern**

Status können bearbeitet werden, indem Sie auf die Schaltfläche mit dem Bleistiftsymbol rechts neben dem Status klicken.

![](https://raw.githubusercontent.com/catenda/help-center/main/images/g7ntz7r8/03-changing-statuses.png)

Die Farbe und der Name eines Status können geändert werden.

![](https://raw.githubusercontent.com/catenda/help-center/main/images/g7ntz7r8/04-changing-statuses.png)

### 4.1 **Sortierreihenfolge**

Klicken Sie nach der Bearbeitung auf die Pfeile, um den Status in der Liste der Status in seiner Phase nach oben und unten zu verschieben.

### 4.2 **Status archivieren**

Status können archiviert werden, indem Sie auf die Schaltfläche "Papierkorb" rechts neben dem Status klicken. Es ist nur möglich, den Status in derselben Phase zu archivieren und wiederherzustellen. Wenn der jetzt archivierte Status auf Informationen angewendet wurde, wird der Status sichtbar, aber durchgestrichen.

### 4.3 **Status wiederherstellen**

Archivierte Status können jederzeit wiederhergestellt werden, indem Sie auf "Archivierte Status anzeigen" klicken. Hier werden alle archivierten Status angezeigt und können wiederhergestellt werden.

## 5. Standardstatus

Der Status, der standardmäßig angezeigt wird, wenn die Veröffentlichungsaktion für eine gemeinsame Überarbeitung verwendet wird. Ein anderer Status kann dennoch vor der Veröffentlichung ausgewählt werden. Gemeinsame Überarbeitungen können auch über [Genehmigungsanfragen](https://support.catenda.com/en/articles/12494960-open-or-closed-approval-request-page) veröffentlicht werden. Abhängig davon, welchen Workflow der Einreichende im Namen ihres Einreichungsteams ausgewählt hat, wenn ein Mitglied eine abschließende Validierung im Namen des endgültigen Validierungsteams durchführt, ändert sich der Status des Dokuments der veröffentlichten Überarbeitung auf der Grundlage der Workflow-Konfiguration.

## 6. Upload-Menü

### 6.1 **Gemeinsame Status aktiviert**

So kann das Upload-Menü aussehen, wenn der veröffentlichte und gemeinsame Workflow für ein Projekt aktiviert werden soll.

![](https://raw.githubusercontent.com/catenda/help-center/main/images/g7ntz7r8/05-shared-statuses-enabled.png)

Standardmäßig ist der Standard-Gemeinsame-Status "Freigegeben". Ein Status aus der Liste der gemeinsamen Status kann vor dem Upload ausgewählt werden.

### 6.2 **Gemeinsame Status deaktiviert**

So kann das Upload-Menü aussehen, wenn gemeinsame Status deaktiviert sind.

![](https://raw.githubusercontent.com/catenda/help-center/main/images/g7ntz7r8/06-shared-statuses-disabled.png)

Standardmäßig ist der Standard-Veröffentlichte-Status "Kein Status". Ein Status aus der Liste der veröffentlichten Status kann vor dem Upload ausgewählt werden.
