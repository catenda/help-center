# Organisatietypen

Voor een klant kunnen elk aantal organisaties worden aangemaakt, maar op basis van het organisatietype kunnen zij verschillende soorten projecten bevatten.

## 1. **1. Organisatie voor actieve projecten**

Een lopend bouwproject kan deel uitmaken van een organisatie voor actieve projecten. Voor elke organisatie kan een plan worden geconfigureerd. Degenen die verantwoordelijk zijn voor het beheer van Catenda binnen een organisatie kunnen als eigenaar van de organisatie worden ingesteld. Organisatie-eigenaren kunnen toegang krijgen om projecten aan te maken door een plan te configureren met een projectlimiet voor de organisatie. De volgende enterprise-plannen zijn beschikbaar:

### 1.1 **1.1 Maximaal projectaantal**

Met dit plan kunnen er tegelijkertijd tot een bepaald aantal projecten zijn.

### 1.2 **1.2 Organisatie naar projectgrootte**

De soorten projecten in deze organisatie hangen af van de grootte van elk project. Gelijkmatig grote projecten worden in dezelfde organisatie gegroepeerd.

### 1.3 **1.3 Onbeperkte projecten**

In dit soort organisatie kunnen elk aantal projecten worden aangemaakt. Om veiligheidsredenen wordt voor dit soort organisaties vaak een projectlimiet ingesteld die hoger ligt dan wat waarschijnlijk bereikbaar is.

### 1.4 **1.4 Educatieve instellingen**

Projecten van studenten in recente onderwijsperioden worden vaak in dit soort organisaties bewaard.

**Vervaldatum** Voor de organisatie wordt vaak een vervaldatum ingesteld zodat projecten die in deze organisatie worden aangemaakt na een bepaalde tijd verlopen. Als een vervaldatum voor een educatieve organisatie is ingesteld, is deze vaak ingesteld op 365 dagen na projectaanmaak. De vervaldatum die voor de organisatie is geconfigureerd, geldt alleen voor nieuwe projecten die in de organisatie worden aangemaakt. De vervaldatum op bestaande projecten kan alleen door Catenda per project worden gewijzigd.

> **Opmerking:** Docenten kunnen projecten voorbereiding het begin van de onderwijsperiode, dus kan de totale periode nadat een student het project in handen krijgt korter zijn.

## 2. **2. Organisatie voor inactieve projecten**

Breng projecten over naar een organisatie voor inactieve projecten om ruimte vrij te maken in de organisatie voor actieve projecten. Activiteit van projectleden in dit soort projecten wordt gemonitord. Als meer activiteit van projectleden wordt opgemerkt dan verwacht voor een inactief project, zal het project als actief project worden geteld. Theoretisch is het daarom mogelijk om elk aantal leden in een project in dit soort organisatie te hebben, maar het wordt aanbevolen om de ledenlijst in te korten. Het organisatiegereedschap wordt vaak gebruikt om alle leden behalve de hoofdleden die verantwoordelijk zijn voor het project en organisatiebeheerders te verwijderen.

### 2.1 **2.1 Projecten in de wacht**

Een typisch project in deze organisatie is een stilgelegd project. Projecten kunnen om veel redenen stilliggen, bijvoorbeeld wanneer een bouwproject geen budget meer heeft of wanneer middelen naar andere projecten moeten worden herverdeeld.

### 2.2 **2.2 Niet meer in gebruik**

Andere use cases voor dit soort organisatie kunnen projecten omvatten die niet meer worden gebruikt maar die mensen wat langer willen behouden. Een reden om een project op Catenda te houden kan zijn dat het project is afgelopen, maar er nog geen tijd is geweest om alle informatie te exporteren, of omdat er nog geen archiveringsoplossing beschikbaar is.

**Archief** In tegenstelling tot andere oplossingen die speciaal gericht zijn op langetermijnarchivering van informatie, is Catenda bedoeld voor actieve samenwerking. In enkele landen moet Catenda volgens de wet zodra het project klaar is de gegevens verwijderen. In situaties waarin niet vereist is dat het project moet worden verwijderd, kunnen projecten wat langer worden behouden. Projecten worden vervolgens vaak naar een archieforganisatie verplaatst.

## 3. **3. Admin-projectorganisatie**

Een admin-organisatie wordt aangemaakt zodra het eerste testproject wordt aangemaakt. Wanneer een enterprise-overeenkomst wordt gesloten, wordt een admin-organisatie aangemaakt als deze nog niet bestaat.

### 3.1 **3.1 Project met nieuwe functies**

Als er op enig moment vragen opkomen tijdens de klantenreis, kan een aparte organisatie genaamd admin worden aangemaakt als deze nog niet bestaat. In de organisatie kunnen projecten worden aangemaakt zodat deze niet meetellen voor het totale aantal actieve projecten. Om de vragen op te lossen, kan een project in zo'n organisatie worden aangemaakt zodat een specifieke installatie of configuratie kan worden geprobeerd of nieuwe functies die nog niet voor alle gebruikers beschikbaar zijn, kunnen worden ingeschakeld en voor activering op actieve projecten worden overwogen.

**Vervaldatum** Een vervaldatum kan voor de duur van de testperiode worden ingesteld zodat de vraag kan worden opgelost. De vervaldatum kan alleen door Catenda per project worden gewijzigd.

### 3.2 **3.2 Sjabloonproject**

Elke admin-organisatie bevat meestal een sjabloonproject. Nadat de eerste paar projecten afzonderlijk zijn geconfigureerd, wordt door Catenda vaak een sjabloonproject in de admin-organisatie aangemaakt. In dit project worden typische projectconfiguraties aangemaakt zodat het project kan worden gebruikt als sjabloonproject voor het aanmaken van nieuwe projecten. Typische projectconfiguraties kunnen het volgende omvatten: Benoemde, lege modellen op de modelenpagina. Onderwerpborden met geconfigureerde instellingen zoals statussen, typen en aangepaste velden. Documentenpagina met mappenstructuur en mapconfiguratie met aangepaste velden en naamgeving. Toegangsbeheer kan voor al deze zaken worden geconfigureerd voor gebruik in het nieuwe project. Projectinstellingen zoals aangepaste velden en naamgevingsconventies.

### 3.3 **3.3 Administratieve projecten**

Administratieve projecten worden vaak in deze organisatie aangemaakt voor interne communicatie en voor discussie over gesprekken met Catenda. Dit soort projecten heeft meestal geen vervaldatum.

### 3.4 **3.4 Actieve testprojecten**

Testprojecten worden in deze organisatie vaak aangemaakt of heropend zolang ze niet voor echte bouwprojecten worden gebruikt. Deze projecten krijgen vaak een vervaldatum zodat Catenda kan worden getest zonder het actieve project te beschadigen.

### 3.5 **3.5 Inactieve testprojecten**

Projecten die tijdens eerdere testfasen zijn gebruikt, kunnen in deze organisatie worden gevonden. Dit zijn doorgaans projecten zoals: Onderwijsprojecten Testprojecten Sandbox-projecten

**Vervaldatum** Een vervaldatum kan voor de duur van de testperiode worden ingesteld zodat het project actief blijft maar niet langer toegankelijk is. De vervaldatum kan alleen door Catenda per project worden gewijzigd en wordt vaak overgenomen uit de organisatieconfiguratie waarin het project is aangemaakt.

### 3.6 **3.6 Voorbeeldprojecten**

Voorbeeldprojecten kunnen projecten omvatten die zijn afgerond en goed waren geconfigureerd. Exemplarische projecten worden vaak naar de admin-organisatie verplaatst om aan mensen te laten zien wat een echt project zou kunnen zijn.
