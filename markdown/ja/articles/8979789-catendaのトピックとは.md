# Catendaのトピックとは？

何かを行う際の基本は、それが何であれコミュニケーションです。コミュニケーションなしでは素晴らしいことができますが、誰も知ることはできません。Catendaではこのコミュニケーションはtopicの形式をとります。topicは発生したコミュニケーションの記録です。

## 1. **対面コミュニケーション**

最も印象的なコミュニケーション形式は常に対面コミュニケーションです。顔の表情や身体の動きなど、他の方法では得られないニュアンスが存在します。

### 1.1 **対面コミュニケーションの課題**

対面でコミュニケーションできることが常に可能ではないだけでなく、会話を物理的に記録せずに時間が経つほど、コミュニケーションに参加した人誰もが起こったことの一部を忘れる可能性が高くなります。

### 1.2 **コミュニケーションの記録**

元々、これはペンと紙で手作業で情報を書き留めることで解決されていました。ただし、これにも課題があります。インク、筆記用具、用紙などの機器に問題が生じる可能性があるためです。すべてが順調に進み、コミュニケーションが物理的に記録されたとしても、その真正性の問題があります。

### 1.3 **物理的に記録されたコミュニケーションの課題**

誰が書いたのかをどうやって判断できますか?人の筆跡は見ることができますが、これは偽造される可能性があります。

**コミュニケーション履歴**このコミュニケーションはいつ記録されたのか?インクと用紙の炭素年代測定を行うことができるかもしれませんが、誰もがこの技術にアクセスできるわけではありません。記録は時間とともに変更される可能性もあります。異なる色のインクや用紙のテクスチャの追記から発見できるかもしれませんが、これは信頼できるものではありません。

**検索可能性**どの用紙にコミュニケーション情報があったのか?歴史的に、これらの用紙の枚数が増えるにつれて、会話の記録を調べることは問題になってきました。

**可用性**その用紙はどこにあるのか？これはセキュリティの問題であることが多いですが、メンテナンスの問題でもあります。記録を管理することにどのような価値があるのでしょう。保管の怠慢により記録が失われたり、物理文書が遠く離れた場所にあるためにアクセスが失われたりするだけです。

## 2. **デジタルコミュニケーション**

そして、私たちの多くはデジタル方式での記録に移行しています。今日、多くの人が慣れているコミュニケーションの典型的な形式は、メールまたはチャットメッセージです。これはすでに想像できるように、物理紙の課題の大部分に対処しています。

**概要**メールやチャットメッセージなどのプライベートメッセージングは1対1では優れていますが、より多くの人が関わり始めるとすぐに問題が生じます。建設プロジェクトのすべてのメンバーが同時に会話しているグループチャットを想像してください。すべてに対応することが不可能になるだけでなく、重要な会話は情報の流れの中で失われる可能性があります。

**責任**メール会話でも同じことが観察できます。多くの方が、出入りする人々、返信に対する返信、さらに返信が続き、多くの人がccに含まれているが、実際には2人だけがこの会話に参加する必要があるような長いメールスレッドの一部だったことは確かです。この問題の1つは、メッセージがグループの人々に送信された場合、受信者の誰もこの会話への返信に個人的な責任を感じていないということです。

**情報フロー**すべてのユーザーが返信記録にアクセスできるようにしたいが、必ずしも「全員に返信」をして、メールチェーンの一部であるすべてのユーザーに通知したくない場合、返信することも不快な場合があります。

## 3. **Topicとは?**

最後にCatendaトピックに到達しました。トピックは、建設プロジェクトで発生するすべてのコミュニケーションを追跡することを目的としています。1つのコミュニケーションを1つのトピックに記録できます。

- _<a class="intercom-content-link" target="_blank">履歴</a> -_ topicが記録および修正された日時を確認できます。
- _検索可能性_ - topic内のテキストは[検索](https://support.catenda.com/en/articles/8370693-filtering-in-a-topic-board)でき、[ラベルを適用](https://support.catenda.com/en/articles/4670265-labels-page)して、探しているコミュニケーションの重要な部分を見つけることができます
- _可用性_ - プロジェクトが正しく設定されている場合、[右のユーザーは常にアクセス](https://support.catenda.com/en/articles/4670296-topic-boards-acl)できます。インターネット接続がある任意の場所から正しい情報へ([接続がない場合でも!](https://support.catenda.com/en/articles/7325268-offline-mode-in-catenda-site))
- _概要_ - トピックは異なる[トピックリスト](https://support.catenda.com/en/articles/6379614-topic-board-from-an-existing-topic-board)に分割でき、1つの会話フローを別の会話フローから分離できます。
- _[責任](https://support.catenda.com/en/articles/8400566-topic-header#h_dec8c710f5)_ - Topicをユーザーに割り当てて、各会話に対処する責任があるユーザーを明確にできます
- _情報フロー_ - topicにアクセス権を持つすべてのユーザーは最初に作成されたときに通知されますが、topicの進行について[通知](https://support.catenda.com/en/articles/7439223-notifications-page)される適切なユーザーセットを確認できます。
