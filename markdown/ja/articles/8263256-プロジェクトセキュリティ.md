# プロジェクトセキュリティ

## 1. **データの保存**

### 1.1 **アクティブ vs 非アクティブアカウントステータス**

企業との積極的な関係の期間中、プロジェクト情報は通常、進行中のアクセスをサポートするためにプラットフォーム組織内で管理されます。一時停止または凍結されているが、アクティブなアカウント構成の一部のままであるプロジェクトは、参照およびメンテナンスアクティビティのためにアクセス可能なままである場合があります。このような場合、プラットフォーム組織がアクティブなステータスを維持している限り、データは利用可能なままです。

### 1.2 **保持と復旧**

プロジェクトが期限切れステータスに移行された、または手動で削除される場合、それがアクティブなプラットフォーム組織に関連付けられなくなったことを示すアクションの場合、プラットフォームは最大3年間プロジェクトデータを維持することができるという意図で設計されています。この予定期間中、企業との積極的な関係が維持されている限り、プロジェクトはいつでも復旧および再度開くことができます。データ保持期間と復元機能は、プロジェクトが位置する管轄区域の法的および規制要件に厳密に従います。ソフトウェアデータ管理に関する現地法がより早い削除を義務付ける場合、その管轄区域の要件は標準的なプラットフォーム動作よりも優先されます。内部または管轄上のニーズに従って情報が保持されていることを確認するために、[利用可能なエクスポートツールの利用](https://support.catenda.com/en/articles/7946690-exporting-all-project-data)は、プロジェクト期限切れまたは削除の前に最終バックアップを実行することをお勧めします。

### 1.3 **ホームソイルのデータ**

標準的なプラットフォームデータは、セキュアで確立された地域でホストされています。現在の構成は一元化されていますが、現地の管轄要件に合わせるために特定の地域内にデータレジデンシーを確立する可能性がある場合があります。ユニークなホスティングまたは「ホームソイル」のニーズを持つ組織は、[support@catenda.com](mailto:support@catenda.com)のサポートに連絡して、潜在的な技術的可能性と構成について議論することをお勧めします。

## 2. **プロジェクト外のユーザーとのデータ共有**

modelとドキュメントの両方を外部の当事者と共有するためにリンクを作成できます。このようなリンクへのアクセス権を持つ誰もが、modelを表示またはドキュメントをダウンロードするためにアカウントは必要ありません。ドキュメントコレクションのオープンURLを作成することで、ドキュメントを共有できます。_アクセス必須:_ プロジェクトメンバー

ModelはブックマークのオープンURLを作成することで共有できます。_アクセス必須:_ 管理者

これらのタイプのURLをすべてのプロジェクトでオフにするようにリクエストすることが可能です。

## 3. **データのダウンロード**

ファイルはドキュメントセクションにドキュメント修正版としてアップロードできます。

### 3.1 **アクセス制御によるダウンロードの制限**

**ドキュメント / model**ドキュメントへのアクセスは個別に制御できます。IFCドキュメントへのアクセスが制限されている場合、ドキュメントへのアクセス権を持つユーザーのみがそれを表示できます。ドキュメントへのアクセス権を持つメンバーはそれをダウンロードすることができます。

**トピック**トピックへのアクセスはトピックボードごとに制御できます。トピックボードへのアクセスが制限されている場合、トピックボードへのアクセス権を持つユーザーのみがボード内のトピックを表示できます。トピックボードへのアクセス権を持つメンバーは、トピックをBCF、PDF、およびExcelにエクスポートできます。

### 3.2 **修正版の引き出しによるダウンロードの制限**

修正版がドキュメント内に存在し、そこにあるべきではない場合、管理者は修正版を引き出すことができます。修正版が引き出された後、誰もそれをどこでも表示またはダウンロードすることはできません。

### 3.3 **単一トピックのダウンロードの制限**

ドキュメント、トピック、オブジェクトなどの要素への関係を保持するために、トピックをアーカイブできます。トピックを別のトピックボードに移動できます。その後、トピックボードをアーカイブできます。_アクセス必須:_ 管理者

トピックがアーカイブされたトピックボード内にある間、要素の関係は保持されたままになりますが、関連する要素に表示されなくなります。トピックボードが復元されると、関連要素は再びトピックとの関係を表示します。

### 3.4 Modelのダウンロード制限

ドキュメントがIFCドキュメントである場合、modelにリンクできます。

_プロジェクト内_ ドキュメントがmodelにリンクされている場合でも、ドキュメントへのアクセス権を持つユーザーのみがダッシュボード、modelページ、修正版セレクターに表示されるのを見ることができます。

**外部共有** modelがブックマークのパブリックリンクで共有されている場合、modelプレビューは表示することのみでき、ダウンロードはできません。

オブジェクト情報は、外部で共有されているブックマークには表示されません。

## 4. **データの削除**

**ドキュメント/model**メンバーはドキュメントを削除できますが、プロジェクト内の管理者は常に「削除済み」フィルターで検索することでドキュメントを見つけることができます。このフィルターは言語固有であることに注意してください。

**トピック**削除前に、トピックをBCFにエクスポートできます。そのIDのトピックは削除されますが、BCFでIDを変更するとトピックを再度インポートできます。ドキュメント、オブジェクト、トピックなどの要素への関係は失われます。

**マイルストーン**メンバーはマイルストーンをアーカイブおよび復元できます。_アクセス必須:_ マイルストーン作成者または管理者。
