# Desktop Connector トラブルシューティング - すべてのフォルダーがダウンロードされていません

この記事では、[Catenda Desktop Connector](https://support.catenda.com/en/articles/8358861-catenda-desktop-connector)を使用する際に発生する特定のエラーについての情報を見つけることができます。その他の Desktop Connector トラブルシューティング問題については[こちら](https://app.intercom.com/a/apps/areracg3/knowledge-hub/all-content?activeContentId=11844906&activeContentType=article&editorMode=view&native_content=false)をご覧ください。

タスク自体では、以下のような情報が表示されます:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/01-intro.png)

`すべてのフォルダーがダウンロードされていません。クリックしてエラーを表示します。`

この記事では、以下のトピックについて説明します:

## 1. **サポートされていない文字**

この場合、ログファイルには次のエラーが表示されます:

`ファイル名、ディレクトリ名、またはボリューム ラベルの構文が正しくありません。`

Catendaではドキュメント名は命名規則で制限できます。フォルダーは制限できません。命名規則を使用しないと、任意の名前のドキュメントをアップロードできます。この場合、Catendaがドキュメントのファイル拡張子を登録できない可能性があります。任意の名前のフォルダーを作成できます。したがって、Desktop Connectorが、Windowsのパスで使用が許可されていない文字を含むファイルまたはフォルダーの作成を試みる可能性があります。

次の文字で一般的な問題が発生します: `<` - より小さい `>` - より大きい `:` - コロン `"` - ダブルクォート `|` - 縦棒またはパイプ `?` - 疑問符 `*` - アスタリスク

Windowsで予約されている内容の詳細なリストについては、こちらを参照してください: [https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)

## 2. **フォルダーまたはネットワーク パスの欠落**

この場合、ログファイルには次のエラーが表示されます:

`エラー: ネットワーク パスが見つかりません。: '<path>'`

この場合、転送は直ちに失敗します。これは、プログラムがもう利用できないフォルダーにアクセスしようとしているために発生します。"パスウェイ"が完全に壊れているため、プログラムはダウンロードさえ開始できません。フォルダーが"デッドエンド"になった理由は3つあります:

### 2.1 **1. 欠落フォルダー (最も一般的)**

以前に選択されたローカル フォルダーが移動、名前変更、または削除されました。ファイル エクスプローラーでフォルダーの場所に移動しても、フォルダーは存在しません。Desktop Connector がファイルを保存しようとしても、"何もない"という結果になり、停止します。

### 2.2 **2. 壊れた "シンボリック リンク" (隠されたリダイレクト)**

シンボリック リンクは通常のフォルダーのように見えますが、Windowsを別の場所(オフィス サーバーなど)にリダイレクトする永続的な "標識" として機能します。開こうとすると、ポップアップに次のエラーが表示されます:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/02-2-the-broken-symbolic-link-the-hidden-redirect.png)

`場所を利用できません... ネットワーク パスが見つかりません。`

**見分け方:** .lnk ファイルと同様に、シンボリック リンクの場合、フォルダー アイコンの左下に小さな青い "ショートカット矢印" が表示されるか、ショートカットを右クリックして [プロパティ] を選択してください。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/03-2-the-broken-symbolic-link-the-hidden-redirect.png)

[全般] タブでは、[名前] フィールドと [ターゲット] フィールドがグレー表示されます:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/04-2-the-broken-symbolic-link-the-hidden-redirect.png)

**失敗する理由** "標識" はコンピューターにありますが、目的地(例: `Z:` ドライブまたはサーバー)が切断されています。

### 2.3 **3. 壊れた Windows ショートカット (.lnk ファイル)**

標準的な Windows ショートカットは、別の場所のフォルダーを "指す" 小さなファイルです。これらは、独自のハード ドライブ上のフォルダーへのリンクでも、遠くのオフィス サーバー上のフォルダーへのリンクでもかまいません。

**見分け方:**シンボリック リンクと同様に、フォルダーとドライブのショートカットの両方に、フォルダー アイコンの左下に小さな青い "ショートカット矢印" が表示されるか、ショートカットを右クリックして [プロパティ] を選択してください。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/05-3-the-broken-windows-shortcut-lnk-file.png)

[全般] タブで [ターゲット] フィールドを確認します: _ローカル ショートカット_ ターゲットはドライブ文字で始まります(例: `C:\Users\...` または `D:\Data`)。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/06-3-the-broken-windows-shortcut-lnk-file.png)

_ネットワーク ショートカット_ ターゲットはサーバー パス(例: `\\ServerName\Folder`)またはマップされたネットワーク ドライブ文字(例: `Z:\ProjectData`)で始まります。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/07-3-the-broken-windows-shortcut-lnk-file.png)

ダブルクリック時の異なる動作 Windows は、"壊れた" ローカル ショートカットを "壊れた" ネットワーク ショートカットよりもはるかに高速に処理します。

**ローカル ショートカット ("削除" エラー):**コンピューター上のフォルダーが削除された場合、Windows はすぐにそれを認識します。ショートカットをダブルクリックすると、次のエラーが即座に表示されます:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/08-3-the-broken-windows-shortcut-lnk-file.png)

**`このショートカットが参照している項目が変更、移動、または削除されています。`**

**ネットワーク ショートカット ("ハング" エラー):**ショートカットがオフィス サーバーを指していて、オフラインになっている場合(または VPN から外れている場合)、Windows はすぐには目的地がないことを認識しません。最初にネットワーク上でサーバーを "検索" しようとします。マウス カーソルが読み込み中の円に変わり、ウィンドウが 30～60 秒間 "ハング" または一時停止した後、最後に次のように表示される可能性があります:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/09-3-the-broken-windows-shortcut-lnk-file.png)

**`ショートカットが参照しているドライブまたはネットワーク接続が利用できません。`**

Desktop Connector にこれらのショートカットの 1 つを使用するように指示されている場合、ターゲットが見つからないか、ネットワークが停止していると、プログラムは最終的に Windows がパスを検索するのを待っている間に "タイムアウト" します。Desktop Connector が作業を開始するための有効な目的地を見つけることができないため、停止してエラーを報告します。

### 2.4 **その修正方法**

**切断を確認する** Windows エクスプローラーで移動先フォルダーを開いてみてください。移動先フォルダーが見つからない場合は、その場所に新しいフォルダーを作成するか、Desktop Connector で別のフォルダーを選択する必要があります。

**再接続または再選択** "ネットワーク パスが見つかりません" または "ドライブが利用不可" エラーが表示される場合は、ネットワーク パスまたはドライブへの接続を確認してください。"このPC" に移動し、ネットワーク ドライブ (例: `Z:`) がアクティブであることを確認してください。外部 USB ドライブまたはハード ドライブが正しく接続されているかどうかを確認してください。赤い X がある場合は、ダブルクリックして再接続してください。ネットワーク ドライブがアクティブでなく、そのドライブがあるネットワークがわかっている場合は、ケーブルをプラグインするか、wifi 経由で参加するか、VPN を使用している場合は、VPN がアクティブかどうかを確認してネットワークに再接続してください。ドライブが利用できなくなった場合は、Desktop Connector でローカル コンピューターまたはネットワーク上で利用可能な別の移動先フォルダーを選択してください。

**削除/名前変更して再作成**ローカル フォルダーまたはショートカットが再起動後も "スタック" したままの場合: 問題のあるフォルダーまたはショートカット ファイルの名前を変更するか(例: `ProjectData` を `ProjectData_OLD` に名前変更)、削除します。同じ名前の新しい標準フォルダーを作成します。転送を再開してください。Desktop Connector が新しい状態の良いフォルダーを検出し、通常の操作を再開します。

**欠落フォルダーの代わりに一時フォルダーが作成されなかった理由は何ですか?**他の状況では、Desktop Connector は何か問題が発生したときに、名前に `_restricted` が付加されたフォルダーを作成します。ただし、Windows が "欠落" 場所を処理する方法には技術的な違いがあります:

`_restricted` フォルダーは、フォルダーが "物理的に" 存在しているが "ロック" されている場合(ボルトで固定された部屋への出入り口のように)にのみ作成されます。その場合、プログラムは扉を見て、その横に新しい1つ(`_restricted`)を構築することを決定します。

欠落パスの場合は異なります。フォルダーはもう存在しないか、選択された "標識"(シンボリック リンク)が空の場所を指しています。プログラムにとって、単にロックされているだけではなく、建物全体から "部屋" 全体が消えています。最初から "出入り口" がないため、プログラムは `_restricted` バージョンを作成できず、停止する必要があります。

## 3. **マウント ポイントの欠落**

この場合、ログファイルには次のエラーが表示されます:

`エラー: パスの一部を見つけることができませんでした '<path>'。`

フォルダーが開けない場合、Windows は "標識" をネットワーク場所にたどろうとし、次のエラーが表示されます:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/10-missing-mount-point.png)

`<Path> にアクセスできません。` `ネットワーク パスが見つかりません`

この場合、Desktop Connector は、名前に "\_restricted" が付加された新しいフォルダーを自動的に作成します(例: `ProjectData_restricted`)。

これは、コンピューター上のフォルダーが別のドライブへの "マウント ポイント" (出入り口)である場合に発生します。他のドライブの例には、次のものが含まれます:

- USB スティック、
- 外部ハード ドライブ
- 現在切断されているネットワーク ボリューム。

Windows はフォルダーの存在を "記憶" しますが、物理ドライブが見つからないため、フォルダーは "ゴースト" になります。Desktop Connector はフォルダーが存在することを検出しますが、書き込みできません。データが失われるのを防ぐため、`_restricted` サフィックス付きのシャドウ フォルダーが作成され、ファイルが安全な場所に着地するようになります。

これが発生する可能性がある一般的な状況を次に示します:

- フォルダーが、抜き出されたドライブ(例: `D:`)にマップされていました。
- フォルダーは、オフラインまたは VPN が必要なネットワーク共有(例: `Z:`)を指しています。
- クラウド サービス(Dropbox、OneDrive、またはその他のコラボレーション ツール同期サービス)が、現在アクティブでない "プレースホルダー" フォルダーを作成しました。
- エンタープライズ セキュリティ ツールがサード パーティ アプリケーションによる変更からフォルダーを "シールド" しています。

フォルダーが "ゴースト" かどうかを確認するには、フォルダーを右クリックして [プロパティ] を選択します。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/11-missing-mount-point.png)

[全般] タブの [種類] フィールドを確認します: 通常のフォルダーは "ファイル フォルダー" と表示されますが、ゴースト フォルダーは "マウント ボリューム" と表示されます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/12-missing-mount-point.png)

マウント フォルダーをダブルクリックすると、次のエラーが即座に表示されます:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/3s5dragb/13-missing-mount-point.png)

**`場所を利用できません`**または

**`ネットワーク パスが見つかりません`** `<Path> は利用できないようにリンクが壊れています`

### 3.1 **その修正方法**

フォルダーを手動で再作成する フォルダーが再起動後も "スタック" したままの場合:

1. 問題のあるフォルダーの名前を変更します(例: `ProjectData` を `ProjectData_OLD` に名前変更します)。
1. 元の名前で新しいフォルダーを作成します(`ProjectData`)。
1. Desktop Connector は新しい状態の良いフォルダーを検出し、`_restricted` サフィックスなしで通常の操作を再開します。

**ハードウェアまたはネットワークを再接続する** "このPC" に移動し、ネットワーク ドライブ (例: `Z:`) がアクティブであることを確認してください。外部 USB ドライブまたはハード ドライブが正しく接続されているかどうかを確認してください。赤い X がある場合は、ダブルクリックして再接続してください。ネットワーク ドライブがアクティブでなく、そのドライブがあるネットワークがわかっている場合は、ケーブルをプラグインするか、wifi 経由で参加するか、VPN を使用している場合は、VPN がアクティブかどうかを確認してネットワークに再接続してください。ドライブが利用できなくなった場合は、Desktop Connector でローカル コンピューターまたはネットワーク上で利用可能な別の移動先フォルダーを選択してください。

**削除/名前変更して再作成**ローカル フォルダーまたはショートカットが再起動後も "スタック" したままの場合: 問題のあるフォルダーまたはショートカット ファイルの名前を変更するか(例: `ProjectData` を `ProjectData_OLD` に名前変更)、削除します。元の名前で新しいフォルダーを作成します(`ProjectData`)。転送を再開してください。Desktop Connector が新しい状態の良いフォルダーを検出し、`_restricted` サフィックスなしで通常の操作を再開します。
