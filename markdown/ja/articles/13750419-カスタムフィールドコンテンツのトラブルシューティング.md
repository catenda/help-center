# カスタムフィールドコンテンツのトラブルシューティング

この記事では、以下のトピックについて説明します。

## 1. **アーカイブされたドロップダウンオプションを復元できない**

アーカイブされたオプションの復元を試みる際に、関連付けられた**名前**が現在アクティブなオプションによって使用されている場合、論理的なデッドロックが発生します。名前を1つのオプションにのみ割り当てることが可能であるため、復元はブロックされます。_必要なアクセス:_ 管理者アクセス

アーカイブされた値を復旧するには、次の手順に従うことが可能です。

**アクティブな値の名前を変更**現在その名前を使用しているアクティブなオプションは、管理者によって一時的な値に編集され、システム内の名前を解放します。

**アーカイブされた値を復元** **無効リスト**にアクセスし、必要なアイテムに対して**復元**アクションが選択されます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/01-unable-to-restore-archived-dropdown-option.png)

**データを修正**名前とコードが正しい状態に調整されます。

**名前を元に戻す**一時的な名前が元の意図した名前に変更されます。

## 2. **名前とコードの一意性**

オプションの**名前**とその**コード**を区別することが重要です。各ドロップダウンオプションはこれら両方の要素で構成され、特定のカスタムフィールド内で名前とコードの両方が一意である場合にのみオプションを保存することが可能です。

## 3. **重複する名前エラー**

ドロップダウンリスト内の1つのオプションに名前を割り当てることが可能です。重複する名前エラーが表示される場合、次の手順が実行されます。_必要なアクセス:_ 管理者アクセス

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/02-duplicate-name-error.png)

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/03-duplicate-name-error.png)

**アクティブリストの確認**アクティブなオプションのリストをチェックして、名前が既に使用されているかどうかを確認します。

**無効リストの確認**アーカイブされたアイテムに割り当てられた名前はシステムに残っているため、無効リストをチェックします。

**解決**異なる一意の名前を使用するか、その名前を保持している既存のオプションの名前を変更することによってのみ進行することが可能です。

## 4. **重複するコードエラー**

ドロップダウンカスタムフィールド内の単一のオプションにコードを割り当てることが可能です。コードは、命名規則のブロックを識別するために使用される一意の値です。_必要なアクセス:_ 管理者アクセス

重複するコードエラーが表示される場合:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/04-duplicate-code-error.png)

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/05-duplicate-code-error.png)

**アクティブリストの確認**アクティブリストをチェックして、コードが既に使用されているかどうかを確認します。

**無効リストの確認**アーカイブされたアイテムに割り当てられたコードはその一意の値を占めたままであるため、無効リストをチェックします。

**解決**異なる一意のコードを使用するか、そのコードを保持している既存のオプションを無効にすることによってのみ進行することが可能です。

## 5. 既存のコードの変更

オプションの初期作成中、またはすでに存在するオプションがまだコードを割り当てていない場合にのみ、コードを定義することが可能です。コードが追加され保存されたら、その値にロックされ、フィールドは編集不可になります。

**編集の制限**コードが適用された後、オプションの**名前**を変更することが可能です。**コード**フィールドはグレーアウトして表示されます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/06-modifying-existing-codes.png)

適用前:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/07-modifying-existing-codes.png)

適用後:

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/08-modifying-existing-codes.png)

**コードの復旧**アーカイブされたアイテムによってコードが既に使用されている場合、無効リストからアーカイブされたオプションを最初に復元することによってのみその特定のコードを使用することが可能です。技術的に無効なアイテムによってまだ保持されているコードを使用して新しいオプションを送信することはできません。

**コードの変更**既存の名前に対して完全に異なるコードを使用するには、現在のオプションを無効にし、目的のコードで新しいコードを作成することによってのみ可能です。

## 6. 整数フィールドの入力エラー

データ入力エラーをもたらす整数フィールドの特定の制約が存在します。

**整数のみ**整数カスタムフィールドに整数のみを保存することが可能です。

**数字以外の文字**フィールドに直接数字を入力することが可能ですが、数字以外の文字を貼り付けることが可能です。

**保存ボタンの動作**フィールドに数字以外の文字が存在する場合、保存ボタンは無効になります。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/09-input-errors-for-integer-fields.png)

## 7. **ボード表示とフィルター**

カスタムフィールドが課題ボードに表示されない場合、次の設定が確認されます。

**フィールド割り当て**カスタムフィールドを作成すると、課題ボードに追加することが可能になります。フィールドは、課題ヘッダーに表示されるように特定のボードに追加する必要があります。

**テーブルビュー**対応する列が課題ボードのテーブルビューで選択されている場合にのみ、カスタムフィールドデータをリスト形式で表示することが可能です。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/10-board-visibility-and-filtering.png)

![](https://raw.githubusercontent.com/catenda/help-center/main/images/b99swgb4/11-board-visibility-and-filtering.png)

**フィルター制限**割り当てられたフィールドが最大10個の場合にのみ、カスタムフィールドをフィルターすることが可能です。
