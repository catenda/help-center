# ステータスワークフロー 共有 → 公開

## 1. **プロジェクトの可用性**

新しいステータスワークフローは、継続中のプロジェクトで有効にするためにリクエストできるオンデマンド機能です。新しいステータスワークフローが有効になっているテンプレートプロジェクトに基づいて作成された新規プロジェクトも、新しいステータスワークフローが有効になります。

**ドラフトは廃止され、利用できなくなります。**

## 2. **共有リビジョンでのステータスワークフローの有効化**

レガシーステータスワークフロー(旧版)の「ドラフト」は、レガシーステータスワークフローを使用していない継続中のプロジェクトの新しいステータスワークフロー(共有ステータス付き)に置き換えられます。共有ステータスは、ドキュメント設定ページのステータスワークフローメニューで有効化できます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/h48tax1e/01-enabling-status-workflow-with-shared-revisions.png)

「ドラフト」のステータスワークフローから「共有」ドキュメントのステータスワークフローへのアップグレードは、次の影響をもたらします；

## 3. **Catenda Hub**

**共有ステータス**プロジェクトで共有ステータスが利用可能になると、すべてのアップロードは共有ステータスで開始されます。アップロード後、共有ドキュメントは公開できます。

**ドラフトドキュメント**ドラフトは廃止されるため、新しいドラフトはアップロードできなくなります。既存のドラフトは旧プロジェクトで引き続き使用できます(制限あり)

🖥️  _ワークスペースおよび_ ✔️ _公開タブ_ 別々のタブ（ワークスペースおよび公開タブ）がドキュメント領域で利用可能になります。公開タブは公開リビジョンのみを提供します。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/h48tax1e/02-catenda-hub.png)

新しいリビジョンナンバリング形式(major.minor)が表示されます。**共有リビジョン**の場合は #0.1、#0.2 など、**公開リビジョン**の場合は #1、#2、#3 などのようになります。

### 3.1 _アクセス制御_

共有リビジョンの公開に対してアクセス権を設定できます。これにより、ユーザーは共有リビジョンを公開し、公開ステータスを変更できます。アクセス制御はフォルダ/ドキュメントレベルで表示され、ユーザーに書き込みアクセス権でドキュメントリビジョンを公開する権限を与えます。共有リビジョンの閲覧に関するアクセス権が利用可能になります。ここで、「読み取りアクセス」を持つユーザーが共有リビジョンを表示できないようにできます。

**承認**承認リクエストに追加できるのは共有リビジョンのみです

**コレクション**コレクションは公開リビジョンにのみ使用できます

**ドキュメントモデル**モデル領域は、ドキュメント領域と同じようにタブ(ワークスペースおよび公開)を表示します。アクセス権はドキュメントから継承されます。

> **注:** 既存のプロジェクトでこの機能を有効化する場合は、プロジェクトメンバーにこれらの変更について通知してください。

## 4. **APIクライアント**

**最新リビジョン** APIコールで特に指定されない限り、ドキュメント(共有または公開が可能)の最新リビジョンが取得されます

**アップロードデフォルト** APIを介したアップロードは、プロジェクトで共有ステータスが利用可能になると、デフォルトで共有リビジョンになります。

**リビジョン番号の変更**リビジョン番号はCatenda Hubのリビジョン番号(major.minor)と一致しません。アプリを更新する必要があります。

> **注:** 既存のプロジェクトでこの機能を有効化する場合は、プロジェクトメンバーにこれらの変更について通知してください。

[ここ](https://support.catenda.com/en/articles/12289689-status-workflow-api-updates)をクリックして、API変更の詳細を確認してください
