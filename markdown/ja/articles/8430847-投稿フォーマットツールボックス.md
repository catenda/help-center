# 投稿フォーマットツールボックス

> 投稿を作成できるフィールドをフォーマットする方法

Catenda Hub全体の異なる投稿には、同じフォーマットルールが適用されます。投稿には、トピックの説明、コメント、承認説明、および承認コメントを含めることができます。投稿を編集できるユーザーへのアクセスが異なるため、バリエーションが適用される場合があります。Catendaはマークダウンを使用してテキストをフォーマットします。これは、文の前後の特定の文字がテキストのスタイルに影響を与えることを意味します。トピックのヘッダーと説明を送信後にどのように表示されるかは以下の通りです：

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/01-intro.png)

## 1. フォーマットの利用可能性

フィールドをフォーマットできることは、フィールドが編集されるときにフィールドの下に表示されるツールボックスで判断できることがよくあります。

> **注:**ブラウザのズームスケールを十分に縮小して、すべてのツールを表示してください。

フォーマットは以下のフィールドで利用可能です：

### 1.1 **トピックの説明とコメント**

既存のトピックの説明またはコメントを編集するか、新しいトピックを送信するときにツールボックスを表示してください：

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/02-topic-description-and-comment.png)

### 1.2 **承認依頼の説明**

ツールボックスは新しい承認依頼ダイアログの説明には表示されませんが、フォーマットはこの説明に適用されます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/03-approval-request-description.png)

> **注:**このフィールドは、承認依頼を送信した後は編集できません。

### 1.3 トピックリストの説明

ツールボックスは新しいトピックリストの説明に表示されますが、ボードが送信されるときに説明がフォーマットされていないことに注意することが重要です。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/04-topic-board-description.png)

## 2. **トピックコメント添付ファイル**

トピックコメントでは、添付ファイルツールが表示されます。トピック内の+ボタンをクリックして、添付ファイルを追加します。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/05-topic-comment-attachment.png)

[ここをクリック](https://support.catenda.com/en/articles/8053352-topic-body-the-content-of-a-topic#h_0e3c0059ae)して、コメント添付ファイルについてさらに詳しく読んでください。

## 3. **テキストのスタイル設定**

次の方法を使用して、テキストをスタイル設定できます：

### 3.1 **太字、斜体、取り消し線**

太字、斜体、取り消し線のスタイルは行の任意の部分で実行でき、行の開始時に行う必要がある他のスタイルと組み合わせるとうまく機能します。

### 3.2 **見出し**

見出しツールは、行の開始部分にハッシュタグ/パウンドサイン（#）を適用します。5つのレベルの見出しがサポートされています。見出しが受け取るフォーマットは、行の開始時にあるハッシュタグ/パウンドサイン（`#`）の量に依存します。

<img alt="" src="https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/inline-c21079ec7efb.png" width="290"/>   \<->   <img alt="" src="https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/inline-557784a5d702.png" width="290"/>

### 3.3 **リンク**

リンクのスタイル設定は行の任意の部分で実行でき、行の開始時に行う必要がある他のスタイルと組み合わせるとうまく機能します。説明内のリンクは緑色で下線が引かれます。テキストはリンクが指すURLと異なる場合があります。URLは自動的にクリック可能なリンクに変わります。

```
https://hub.catenda.com
```

[https://hub.catenda.com](https://hub.catenda.com)になり、

```
[Catenda Hub](https://hub.catenda.com)
```

[Catenda Hub](https://hub.catenda.com)になります

> **注：** リンクをクリックする際は注意してください。括弧内のテキスト[from the brackets]は1つのリンクを表示する場合がありますが、括弧内の実際のリンク(from the parantheses)は異なる場合があります。リンクをクリックする前に、リンクをホバーして、ブラウザがリダイレクトされる先を確認することをお勧めします。

### 3.4 **フォーマット防止**

単語を非文字または非数字の文字でラップすることで、見た目を異なるものにすることができます。これは常に望まれるわけではありません。そのような文字の前に`\`を置くと、`\`は消えます。これらの文字に適用されたであろうフォーマットは機能しなくなります。[リスト](#h_6da4949f8c)の一部ではない空行に`\`を置くと、結果はやはり空行になります。

## 4. **テキストの分割と構造化**

次の方法を使用して、テキストを分割して構造を追加し、テキストを強化できます：

### 4.1 **画像**

説明内の画像にはリンクが付加される場合があります。画像を埋め込むには、この構文を使用できます

```
![text](https://bimsync.com/img/favicon/dark-mode/favicon-32x32.png)
```

この画像を取得して、その後ろに「text」という単語を付けます。

![テキスト](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/06-images.png)

Catendaが画像を正しく表示するには、提供されたリンクにアクセスする必要があります。

> **注:** \+ 画像を説明に追加できます \+ 画像をテキストと混在させることができるため、同じコメントまたは説明内に画像の前後両方にテキストを含めることができます。 \+ これらのような画像は表とリストと組み合わせることができます。たとえば、行の開始時にのみ機能するフォーマットチェックボックスの代わりに、文/表の中央にチェックマーク画像を追加することができます \- 画像へのリンクが将来も利用可能であることを保証することはできません。

_Catenda画像ドキュメントリンクを取得する_ [ドキュメントを選択した後、ダウンロードアクションボタンを右クリック](https://support.catenda.com/en/articles/4670288-actions-in-the-document-structure#h_133e2bcc57)するか、[ドキュメントを開いた後、最新リビジョンをダウンロードアクションボタンを右クリック](https://support.catenda.com/en/articles/9323521-actions-in-a-document)すると、ドキュメントのダウンロードリンクをコピーできます。上記のようなトピックでこのリンクを使用すると、トピックでCatendaドキュメントを使用できるようになります。

> **注:** \+ Catenda画像ドキュメントへのリンクを追加すると、Catendaにのみ表示され、トピックが交換される可能性のある他のプラットフォームでは利用できない画像を追加できます。 \+ Catenda画像ドキュメントへのリンクを追加することで、ドキュメントにアクセスできるユーザーのみが画像を見ることができます。 \- Catenda画像ドキュメントへのリンクを追加すると、トピックが同期された可能性のある他のプラットフォームには表示されず、ドキュメントにアクセスできないユーザーには表示されません。

### 4.2 **リスト**

**順序なしリスト**順序なしリストを開始するには、その上に空白行を置き、ハイフン（`-`）、プラス（`+`）、またはアスタリスク（`*`）の後に半角スペースを置きます。行の開始部分に4つのスペースまたはタブスペースを挿入して、サブリストを作成します。

```
 - First element - Second element     - Insert 4 spaces at the start of the line to create a sublist。
```

または

```
 + First element + Second element     + Insert 4 spaces at the start of the line to create a sublist。
```

または

```
 * First element * Second element     * Insert 4 spaces at the start of the line to create a sublist。
```

これらはすべて以下のようになります：

- 最初の要素
- 第2番目の要素
  - 行の開始位置に4つのスペースを挿入して、サブリストを作成します。

> **注:**順序なしリストが正しくフォーマットされるには、リストの上の行に空白の改行が必要です。

**順序付きリスト**順序付きリストを開始するには、その上に空白行を置き、番号、ピリオド、スペース（`1. `）を置きます。前の番号が何であるかは問題ではなく、ピリオドが後に続く番号であることだけが重要です。行の開始部分に4つのスペースまたはタブスペースを挿入して、サブリストを作成します。

```
1. item one 2. item two 3. item three     4. item four
```

または

```
1. item one 1. item two 1. item three     1. item four
```

または

```
1. item one 10. item two 1. item three     1000. item four
```

これらはすべて以下のようになります：

1. item one
1. item two
1. item three

1. Item four

> **注:**順序付きリストが正しくフォーマットされるには、リストの上の行に空白の改行が必要です。

開始する番号は番号付けが開始される場所に影響を与えません

```
23. twenty-three 1. twenty-four 1. twenty-five     1. twenty-six
```

次のようになります：

1. twenty-three
1. twenty-four
1. twenty-five

1. twenty-six

同じ投稿内の2番目のリストから番号付けをリセットして1から開始したい場合は、空白行または[区切り線](#h_3a36cfbc61)を間に配置できます。

[リストがフォーマットされるのを防ぐ](#h_2ec17c688b)ために、独自の番号付けを使用できるようにするには: リストの上の行に文字を配置します。`\`を使用することをお勧めします。なぜなら、それは消えるからです。

```
\23. twenty-three 24. twenty-four 25. twenty-five     26. twenty-six
```

ピリオド（`.`）の前にバックスラッシュ（`\`）を置きます：

```
23\. twenty-three 24\. twenty-four 25\. twenty-five     26\. twenty-six
```

これらはすべて以下のようになります：

23\. twenty-three 24\. twenty-four 25\. twenty-five 26\. twenty-six

## 5. **@ メンバーとチームへのメンション**

`@`ツールをクリックするか、説明またはコメントに`@`を記入してメンバーをメンションします。`@`を入力すると、メンバーとチームのドロップダウンリストが表示されます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/10-mentioned-members-and-teams.png)

メール、メンバー名、またはチーム名の入力を開始してリストを検索します。矢印キーでリストを上下に移動し、クリックまたはEnterキーを押してメンバーまたはチームを選択します。メンバーまたはチームがこのリストに表示されるには、メンバーまたはチームがトピックボードに対して少なくとも読み取りアクセス権を持つ必要があります。リスト内のメンバーまたはチームを選択すると、`@`は以下のようなテキストを取得します：

`@[<メンバーのメールアドレス>]`または`@[<チーム名>]`

### 5.1 **トピック内のメンションを保存または送信**

説明が保存されるか、コメントが送信されると、トピックリストへのアクセス権を持つ関連メンバーは通知を受け取ります。メンバーメールまたはチーム名が既知の場合は、手動で記入することもできますが、トピックリストの一部でない場合、関連メンバーはメンションされたことを通知されません。

**メンバーメンション時の通知**トピックリストへのアクセス権を持ちメンションされたメンバーは、トピック内でメンションされたという通知を受け取ります。

**チームメンション時の通知**トピックリストへのアクセス権を持ちメンションされたチームの一部であるメンバーは、メンションされたチームの一部であるという通知を受け取ります。

**今後のトピックイベントに関する通知**トピックの説明とコメントでメンションされたチームのメンバーは、保存された説明または送信されたコメント時にのみ通知を受け取ります。

メンションされたという通知に加えて、投稿でメンションされたメンバーは自動的に[フォロー](https://support.catenda.com/en/articles/8053299-right-panel-in-an-issue#h_a97f3b264e)に設定され、新しいコメントやステータス変更などのトピックイベントに関する通知が表示されます。これは、[割り当て者](https://support.catenda.com/en/articles/8400566-issue-header#h_0a91fa8dd9)と[リクエスター](https://support.catenda.com/en/articles/8400566-issue-header#h_1aea0990a7)だけでなく、より多くのユーザーが今後の変更とトピックに関する通知を受け取るようにする優れた方法です。メンバーがトピックをフォローしたくなくなった場合は、手動でフォロー解除する必要があります。

### 5.2 **投稿内のメンション**

投稿内のメンションは、緑色のテキスト色を持つことで識別できます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/11-mention-in-post.png)

背景では、メンションされたプロジェクト参加者の一意のIDが保存されます。この緑色のテキストに表示されるのは、参加者の名前です。メンバーまたはチームの名前が変更されても、投稿でメンションされたままになりますが、新しい名前の下で表示されます。

メンションされたメンバーには、そのメンバーの[メンバーページ](https://support.catenda.com/en/articles/8228836-member-page)にリダイレクトするクリック可能なリンクがあります。メンションされたチームには、そのチームの[チームページ](https://support.catenda.com/en/articles/7891755-team-page)にリダイレクトするクリック可能なリンクがあります。

**存在しないメンバー**メンションされたメールアドレスを持つプロジェクト内のメンバーがない場合、投稿は代わりに以下のようになります：

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/12-mention-in-post.png)

これは、メールの形式が正しくないか、メンバーがプロジェクトの一部ではなくなったかのいずれかです。このメールアドレスを持つメンバーが将来プロジェクトの一部になった場合、投稿は変更されてそのメンバーの名前を表示します。

**存在しないチーム**チームがプロジェクトから削除され、新しいチームが作成された場合、この新しいチームはメンションされません。新しいチームをメンションするには、投稿を再送信する必要があります。

## 6. **# タグ付きトピック**

`#`ツールをクリックするか、説明またはコメントに`#`を記入してトピックをタグ付けします。`#`を入力すると、すべてのトピックリストからのトピックのドロップダウンリストが表示されます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/13-tagged-topics.png)

タイトルまたはトピック番号の入力を開始してリストを検索します。矢印キーでリストを上下に移動し、クリックまたはEnterキーを押してトピックを選択します。トピックがこのリストに表示されるには、タグ付けしているメンバーがトピックが存在するボードへのアクセス権を持つ必要があります。リスト内のトピックを選択すると、`#`は以下のようなテキストを取得します：

`#[<トピック番号>]`

### 6.1 **タグ付きトピックを保存または送信**

説明が保存されるか、コメントが送信されると、トピックの関係が作成されます。リンクされたトピックは、トピックの[右メニュー](https://support.catenda.com/en/articles/8053299-right-panel-in-an-issue)の[リンクされたトピック](https://support.catenda.com/en/articles/8053299-right-panel-in-an-issue#h_edf2cb07a8)のリストに追加されます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/14-saving-or-submitting-a-tagged-topic.png)

別のトピックがタグ付けされたトピックに加えて、タグ付けされたトピック自体は、トピックの[右メニュー](https://support.catenda.com/en/articles/8053299-right-panel-in-an-issue)の[リンクされたトピック](https://support.catenda.com/en/articles/8053299-right-panel-in-an-issue#h_edf2cb07a8)のリストに追加された場所へのリンクバックを受け取ります。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/15-saving-or-submitting-a-tagged-topic.png)

トピックリンクは、説明内のタグ付きトピックを持つトピック、またはタグ付けされたトピックから削除できます。それぞれのトピックにアクセスして、トピックの[右メニュー](https://support.catenda.com/en/articles/8053299-right-panel-in-an-issue)の[リンクされたトピック](https://support.catenda.com/en/articles/8053299-right-panel-in-an-issue#h_edf2cb07a8)のリストを編集します。

### 6.2 **投稿内のタグ付きトピック**

タグ付きトピックは、最初にタグ付きトピックの現在のステータスの色を持つ円があり、そのステータスの名前が付いていることで識別できます。その後、トピックタイトルが表示され、その後にトピック番号が続きます。

チェックボックスと一緒に、クローズされたタグ付きトピックは上部に表示されるプログレスバーのプログレスにカウントされ、オープンなタグ付きトピックはプログレスがカウントされる総アイテム数にカウントされます。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/tt9y4c9z/16-tagged-topic-in-post.png)

タグ付きトピックには、タグ付きトピックをそのトピックリストで開くクリック可能なリンクがあります。
