# チームの作成

建設プロジェクトではチームが重要です。人が出入りしたり、役割を変更したり、異なるワークグループから去ったりすることが多いためです。チームを設定することで、プロジェクトで役割が変わった後の誤解通を防ぐことができます。

[メンバーとチームページ](https://support.catenda.com/en/articles/4670291-members-and-teams-page)の緑色のプラスボタンの右側にあるアクションメニューを開いてチームを作成します。選択されているタブに関わらず作成できます。

チームはメンバーとチームのコンテンツページからそれぞれ作成することもできます：

## 1. **チームをいつ設定する?**

Catendaチームは、希望する方法で分割できます。通常、チームはプロジェクト参加者が属する各専門分野ごとに作成されます。個別のワークグループまたは学問領域の内部あるいは学際的に別々のチームが作成されることもあります。メンバーは複数のチームに属することができるため、属しているチームはプロジェクト内で担当している異なる役割を説明することになります。

### 1.1 **トピック管理用チーム**

トピックをチームにリクエストして割り当てることで、チームの責任とリクエストを簡単に追跡できます。新しく作成されたトピックは、通常、最初にチームに割り当てられた後、チームのオープンなトピックをレビューし、個々のメンバーがフォローアップするためにトピックがさらに割り当てられます。

### 1.2 **トピック通知用チーム**

トピック内で、チーム全体に何かを知らせるためにチームを言及することもできます。

アクセス制御をチームに委任できます。これを使用して、ユーザーがチームに参加する前にアクセスを設定できます。その後、アクセスの準備ができたら、適切なユーザーをチームに追加できます。この使用方法は、メンバーが招待されたときにチームを設定することで、プロジェクトの一部になるとすぐに適切なアクセス権を取得できるようにします。

## 2. **新しいチームを作成**

新しいチームを作成するページは、次のようになります：

![](https://raw.githubusercontent.com/catenda/help-center/main/images/dwahhbcw/02-create-a-new-team.png)

### 2.1 **名前**

ここにチームの名前を入力します。チーム名はプロジェクトごとに一意である必要があります。

### 2.2 **ロール**

ロール領域では、このチームに参加するメンバーが持つべきロールを設定できます。

**管理者**チームに管理者ロールが付与された場合、そのチームのすべてのメンバーは、メンバーとして管理者であるかどうかに関わらず、管理者アクセス権を持ちます。管理者はプロジェクトへのフルアクセス権を持ちますが、いくつかの例外があります。- プロジェクトの削除。これはプロジェクトオーナーのみが実行できます。- プライベートブックマーク、コレクション、プライベートライブラリ設定などの一部のユーザー固有ビュー。

_メンバー_ - デフォルトメンバーは、デフォルトでほとんどの機能に対する読み取りおよび書き込みアクセス権を持ち、自身のコンテンツの削除アクセス権を持ちます。メンバーは、ドキュメント、トピックリスト、その他のアプリケーションのさまざまなセクションのアクセス制御ルールによってさらに制限できます。

### 2.3 **作成**

チームが作成されると、[チームコンテンツページ](https://support.catenda.com/en/articles/7891755-team-page)が開きます。そこからメンバーをチームに追加できます。
