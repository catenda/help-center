# 新しい承認リクエストの作成 - レガシー

新しい承認リクエストアクションは、[承認ページ](https://support.catenda.com/en/articles/8349340-approvals-page)の緑色のプラスボタンの右側にあるアクションメニューをクリックすることで見つけることができます。

この記事では、以下のトピックについて説明します。

## 1. **承認ヘッダー - 承認の件名**

またはドラフトrevisionの右メニューのapprovalsメニューの新しいapproval作成アクションのアクションをクリックします。新しいワークフローを作成できるのは、すべてのドラフトステータスがアーカイブされていないか、すべてのドラフトステータスがアーカイブされる前にドラフトrevisionがアップロードされたプロジェクトのみです。

新しい承認のヘッダーは次のようになります。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/a5gqwxkx/01-approval-header-the-subject-of-an-approval.png)

### 1.1 **タイトル**

承認リクエストのタイトル。承認を送信するには、少なくともタイトルが必要です。

### 1.2 **発行者**

発行メンバーは、レビュアーから提出されたレビューに基づいて、承認内のドラフトの検証結果に対して最終的な決定権を持ちます。デフォルトでは、発行者はアクセス権を持つ誰にでも設定されます。これは、承認が作成された後、誰でも承認を発行できることを意味します。発行者ドロップダウンをクリックして、メンバーを発行者として構成します。

### 1.3 **作成者**

承認の作成者。

### 1.4 **期日 / マイルストーン**

承認の期日またはマイルストーン。

### 1.5 **レビュアー(オプション)**

ここにコメント、承認、または承認内のドラフトの否定を行うことができるレビュアーを割り当てることができます。_最大レビュアー数:_ 20

### 1.6 **最小レビュアー数**

デフォルトでは、最小レビュアー数は選択されたレビュアーの数です。承認を送信するには、少なくとも1人のメンバーをレビュアーとして選択する必要があります。自分で作業している場合、承認の作成者は、作成している承認をレビュアーが行う場合、自分自身をレビュアーとして設定できます。

最小レビュアー数は、承認を発行するためにレビューを提出する必要があるレビュアーの数です。最小レビュアー数は選択されたレビュアーの数以下である必要があります。選択されたレビュアーの総数より多くの必須レビュアーが存在することはできないためです。_最小レビュアー数: 1_

十分なレビュアーがレビューを送信しない場合、発行者として設定されたメンバーは承認の最終検証を強制することができます。

### 1.7 **承認ボディ - 承認の内容**

新しい承認のボディは次のようになります。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/a5gqwxkx/02-approval-body-the-content-of-an-approval.png)

### 1.8 **説明**

承認の説明は、[投稿の一般的なフォーマットルール](https://support.catenda.com/en/articles/8430847-formatting-of-posts)に従います。

### 1.9 **ドラフト**

検証対象の各ドキュメント内のドラフトrevision。

### 1.10 **ドラフトを追加**

ここをクリックしてドラフトの追加について詳しく読むか、任意の数のドラフトrevisionをドキュメントに追加できます。これにより、承認リクエストの発行により作成される任意の数のトピックが生成されます。

### 1.11 **送信**

送信をクリックして承認を送信します。承認リクエストを送信するには、以下が必要です。

- ドキュメントのドラフトrevisionを最低1つ
- タイトル。

承認リクエストを送信した後も、承認リクエストに変更を加えることができます。

- ドラフトrevisionを含むより多くのドキュメントを追加できます。
- タイトルは変更できます。
- 説明は変更できます。
- ドラフトrevisionは承認リクエストから削除できます。

任意の数のドラフトrevisionをドキュメントに追加して、承認リクエストを作成できます。

新しく作成されたプロジェクトでは、新しいステータスワークフローがデフォルトで有効になります。ステータスワークフローが有効になると、新しいrevisionはアップロード時にドラフトまたは発行されているかどうかを選択できる代わりに、共有revisionとしてアップロードされます。

## 2. **新しいドラフト承認リクエスト**

新しいステータスワークフローが有効にされる前にドラフトrevisionが送信されたプロジェクトでは、新しいドラフト承認リクエストアクションで承認にドラフトを追加し続けることができます。ヘッダーとボディの両方は、新しいステータスワークフローが有効になる前の通常の承認リクエストと同じように機能します。
