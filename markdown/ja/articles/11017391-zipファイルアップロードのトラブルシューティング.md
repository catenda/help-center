# Zipファイルアップロードのトラブルシューティング

## 1. **アップロードに失敗しました**

Catendaへのzipのアップロードには、有線接続の使用をお勧めします。多くのWiFiルーターは正しいデータ受信を確認することに優れていますが、ルーターから遠くにいる場合、最高のルーターでも弱い信号で苦労することがあります。

### 1.1 **ファイルを処理できません**

Zipアップロードプロセス中に、データパケットがCatendaサーバーに送信されます。プロセス中にパケットに問題がある場合、次のメッセージが表示されます：アップロードに失敗しました。ファイルを処理できませんでした。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/qsefpf4z/01-unable-to-process-file.png)

WiFiアンテナの近くにデバイスがある場合でも、パケットが安全に空気中を通過することは100%確実ではありません。この効果は、アンテナから遠くなったり、デバイスとアンテナの間に壁などの物体がある場合に増幅されます。

**大容量ファイル**大量のデータをアップロードする場合、多くのパケットが送信されます。そのうちのいずれかが空気中を経由してルーターに適切に到達しない場合、ネットワークエラーが表示される可能性があります。これが発生すると、アップロード全体が無効になります。

### 1.2 **ネットワークエラー**

特定のソフトウェアは、zipファイル内のファイルへのパスが持つことができる文字数を制限しています。zipファイル内のパス構造に問題がある場合、次のエラーが表示されます: アップロードに失敗しました! ネットワークエラー。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/qsefpf4z/02-network-error.png)

**解凍/再圧縮**このzipが他の誰かから受け取った場合、解凍してから再度圧縮することが役立つ場合があります。

**既知の制限（2025年12月更新）** Microsoft Windows 10/11 Windowsの制限は260文字ですが、増やすことができます。_必要なアクセス：_ Windowsアドミニストレータアカウント

Windowsホームユーザー：このリミットを増やすには、Windowsスタートに移動してREGEDITと入力します。レジストリエディターを開いて以下のパスに移動します：

`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\FileSystem`

`LongPathsEnabled`をダブルクリックして、値を1に変更します。そこにない場合は、`FileSystem`キーを右クリックして選択します

`新規 > DWORD (32-bit) 値`

新しい値に`LongPathsEnabled`という名前を付け、値を1にします。

Windowsプロユーザー このリミットを増やすには、Windowsスタートに移動してgpedit.mscと入力します。グループポリシーエディターを開いて以下のパスに移動します：

`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\FileSystem`

`Win32ロングパスを有効にする`をダブルクリックして有効にします。

### 1.3 **堅牢なアップロード**

**小さいzip** zipが複数のファイルで構成されている場合、zipをより小さいzipに分割できます。各分割されたzipを個別にアップロードできますが、ネットワークまたは接続エラーのリスクは常にあります。

**個別ファイル** [Catenda Desktop Connector](https://support.catenda.com/en/articles/8358861-catenda-desktop-connector)は、ドキュメントをファイルごとにアップロードするため、より安全なアップロード方法です。ブラウザインターフェースを経由するのではなく、ファイルが直接バックエンドにアップロードされるため、これはより高速でもあります。ファイルの1つが失敗した場合でも、その時点までアップロードされたファイルは既にCatendaに表示されます。残りのファイルは、アップロードタスクが次に実行されるときにアップロードが続行されます。

## 2. **特殊文字を含むZipアップロード**

Catendaはzipファイルを抽出する際にそのエンコーディングを検出するため、zipに特殊文字が含まれていれば、抽出時に正しく解釈されます。特殊文字が正しくエンコードされていない場合、Catendaで抽出できなくなり、文字化けして表示されます。zipファイルを作成するのに使用するサービスによって、文字が正しくエンコードされている場合もあれば、そうでない場合もあります。特殊文字が文字化けしている場合は、zip内を確認して、そこに正しく表示されているかどうかを確認してください。文字が正しくエンコードされていると思うが、Catendaで正しく抽出されていない場合は、喜んでzipファイルを確認させていただき、何ができるかを確認します。この場合は、[support@catenda.com](mailto:support@catenda.com)にzipファイルの作成方法の詳細を添えてお問い合わせください。

### 2.1 **WindowsでのZipエンコーディング**

Windowsのバージョンによって、zip エンコーディングが異なります。たとえば、英語版はエンコーディング標準 IBM-437 を使用し、pt-BR版は IBM-850 を使用しています。Windowsインストール環境でzipファイルが正しくエンコードされていない場合は、[7zip](https://7-zip.org/download.html)または[WinRAR](https://www.win-rar.com/download.html?&L=0)などのサードパーティサービスを使用して、正しいエンコーディングでzipファイルを作成する方が成功する可能性があります。

## 3. **完了したが何も起こりない**

Zipインポートが完了した場合でも、ドキュメントテーブルに変更が見えない理由がいくつかあります。これはZipインポートが完了したが、変更が加えられなかった場合の見え方です。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/qsefpf4z/03-completed-but-nothing-happened.png)

これはこの状況でのZipインポートページの右メニューの見え方です：

![](https://raw.githubusercontent.com/catenda/help-center/main/images/qsefpf4z/04-completed-but-nothing-happened.png)

### 3.1 **スキップされたフォルダ**

Zipと同じ名前のフォルダがZipを抽出しようとしている場所に既に存在する場合、フォルダの作成がスキップされ、新しいフォルダは作成されません。同じ名前のフォルダ内のドキュメントはCatendaプロジェクト内の既存フォルダにアップロードされます。

### 3.2 **スキップされたファイル**

Zipアップロードダイアログで[スキップして続行]オプションが選択された場合、Zipファイルからアップロードしようとするファイルと同じ名前のドキュメントが既に存在する場合、それはスキップされ、次のファイルが抽出を開始します。

### 3.3 **見つからないドキュメント**

ドキュメントが見つからないドキュメントの下にリストされている場合、これは、ドキュメントが正常に作成されたが表示できないことを意味します。ファイルがアップロードされたドキュメントが削除されている可能性があります。アップローダーがファイルがアップロードされたドキュメントへのアクセスを失った可能性もあります。_必要なアクセス:_ 読み取りアクセス
