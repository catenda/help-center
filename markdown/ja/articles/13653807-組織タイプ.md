# 組織タイプ

顧客のために任意の数の組織を作成できますが、組織のタイプに基づいて、異なるタイプのプロジェクトが含まれる場合があります。

## 1. **1. アクティブプロジェクト組織**

進行中の建設プロジェクトはアクティブプロジェクト組織の一部になります。各組織に対してプランを設定できます。組織内のCatendaの管理に責任を持つ者は、組織の所有者として設定することができます。組織の所有者は、組織のプロジェクト制限を備えたプランを設定することでプロジェクトの作成へのアクセスを許可することができます。以下のエンタープライズプランが利用可能です:

### 1.1 **1.1 プロジェクトの最大数**

このプランでは、一度に最大で設定された数のプロジェクトを保有できます。

### 1.2 **1.2 プロジェクトサイズ別の組織**

この組織内のプロジェクトのタイプは、各プロジェクトのサイズに依存します。同様のサイズのプロジェクトは同じ組織にグループ化されます。

### 1.3 **1.3 無制限プロジェクト**

このタイプの組織では、任意の数のプロジェクトを作成できます。セキュリティ上の理由から、達成可能性が低いより高いプロジェクト制限がこのような組織に対して設定されることがよくあります。

### 1.4 **1.4 教育機関**

最近の教育期間の学生からのプロジェクトはこれらのタイプの組織に保管されることがよくあります。

**有効期限**有効期限は組織に対してよく設定されるため、この組織で作成されたプロジェクトは設定された時間後に期限切れになります。教育機関に有効期限が設定される場合は、プロジェクト作成から365日に設定されることがよくあります。組織に対して設定された有効期限は、組織で新規に作成されたプロジェクトにのみ適用されます。既存のプロジェクトの有効期限は、Catendaによってプロジェクトごとベースでのみ変更できます。

> **注:** 教授は教育期間の開始前にプロジェクトを準備できるため、学生がプロジェクトを受け取った後の総期間は短くなる可能性があります。

## 2. **2. 非アクティブプロジェクト組織**

プロジェクトを非アクティブプロジェクト組織に転送して、アクティブプロジェクト組織の空きを解放します。このタイプのプロジェクトのプロジェクトメンバーによるアクティビティが監視されます。非アクティブプロジェクトで予想以上のメンバープロジェクトアクティビティが検出された場合、プロジェクトはアクティブプロジェクトとしてカウントされます。理論的には、この種の組織内のプロジェクトに任意の数のメンバーを持つことが可能ですが、メンバーリストを整理することをお勧めします。組織ツールは、プロジェクトと組織の管理者に責任を持つメインメンバーを除くすべてのメンバーを削除するためによく使用されます。

### 2.1 **2.1 休止中のプロジェクト**

この組織の典型的なプロジェクトは休止プロジェクトです。プロジェクトは多くの理由で休止できます。たとえば、建設プロジェクトが予算を使い果たしたとき、または他のプロジェクトにリソースを再配分する必要がある場合などです。

### 2.2 **2.2 使用されなくなった**

このタイプの組織の他のユースケースには、もう使用されていないが、人々がもう少しの間保持したいプロジェクトが含まれる可能性があります。プロジェクトをCatendaに保持する理由は、プロジェクトは終了したが、すべての情報をエクスポートする時間がなかったり、アーカイブソリューションがまだ準備されていなかったりすることがあります。

**アーカイブ**長期的な情報のアーカイビングに特に向けられた他のソリューションとは異なり、Catendaはアクティブなコラボレーションに使用することを目的としています。一部の国では法律により、プロジェクトが完了するとすぐにCatendaはデータを削除する必要があります。プロジェクトを削除する必要がない状況では、プロジェクトをより長く保持したいことがあります。その後、プロジェクトはアーカイブ組織に移動されることがよくあります。

## 3. **3. 管理プロジェクト組織**

管理組織は、最初のテストプロジェクトが作成されるとすぐに作成されます。エンタープライズアグリーメントが入力されたとき、管理組織がまだ存在しない場合は作成されます。

### 3.1 **3.1 新機能プロジェクト**

顧客ジャーニーのいかなる時点で質問が生じた場合、adminという名前の個別の組織がまだ存在していなければ作成できます。組織内で、アクティブプロジェクトの総数に計算されないようにプロジェクトを作成できます。質問に対応するために、特定のセットアップまたは設定を試したり、まだすべてのユーザーが利用できない新機能を有効にしてアクティブプロジェクトでの有効化を検討したりするために、そのような組織内にプロジェクトを作成できます。

**有効期限**テスト期間の間、質問を解決するために有効期限を設定できます。有効期限は、Catendaによってプロジェクトごとベースでのみ変更できます。

### 3.2 **3.2 テンプレートプロジェクト**

各管理組織には通常、テンプレートプロジェクトが含まれます。最初の数個のプロジェクトが個別に設定されてから、テンプレートプロジェクトはCatendaによって管理組織内に作成されることがよくあります。このプロジェクトでは、典型的なプロジェクト構成が作成されるため、プロジェクトを新しいプロジェクトの作成時にテンプレートプロジェクトとして使用できます。典型的なプロジェクト構成には以下が含まれます: モデルページ上の名前付きの空のモデル。ステータス、タイプ、カスタムフィールドなどの設定済みの設定を持つトピックボード。カスタムフィールドとフォルダ構成のあるドキュメントページ、カスタムフィールドと命名規則を備えたフォルダ構成。アクセス制御は、新しいプロジェクトで使用するためにこれらすべてに対して設定できます。カスタムフィールドと命名規則などのプロジェクト設定。

### 3.3 **3.3 管理プロジェクト**

管理プロジェクトはこの組織内で内部通信とCatendaとの会話について議論するために作成されることがよくあります。これらのタイプのプロジェクトは通常、有効期限がありません。

### 3.4 **3.4 アクティブテストプロジェクト**

テストプロジェクトは、実際の建設プロジェクトに使用されていない限り、この組織内で作成または再度開かれることがよくあります。これらのプロジェクトは、アクティブプロジェクトを台無しにすることなくCatendaをテストできるように、有効期限を受け取ることがよくあります。

### 3.5 **3.5 非アクティブテストプロジェクト**

以前のテストフェーズ中に使用されたプロジェクトは、この組織内で見つけられることがよくあります。これらのプロジェクトは通常、以下のようなプロジェクトです: 教育プロジェクト テストプロジェクト サンドボックスプロジェクト

**有効期限**テスト期間の間、プロジェクトがアクティブのままですがアクセスできなくなるように有効期限を設定できます。有効期限はCatendaによってプロジェクトごとベースでのみ変更でき、プロジェクトが作成された組織構成から継承されることがよくあります。

### 3.6 **3.6 サンプルプロジェクト**

サンプルプロジェクトは、完了して適切に構成されたプロジェクトを含めることができます。例示的なプロジェクトは、実際のプロジェクトがどのようなものかを人々に示す方法として、管理組織に移動されることがよくあります。
