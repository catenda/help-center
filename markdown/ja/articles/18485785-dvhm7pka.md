# Microsoft Copilot向けCatenda AI Connectについて

> Catenda AI Connectは、エージェントを通じてCatenda Hubのプロジェクトデータを Microsoft 365 Copilot と Teams に取り込みます。チームでの活用方法、組織での設定、利用の開始方法を説明します。

> **重要:** Catenda AI Connectは早期アクセス版です。機能や設定手順は頻繁に変更されるため、画面に表示される内容がこの記事と異なる場合があります。

> **注:** この記事はサインアウトした読者向けです。このトピックのすべてのレベルへのリンクは、この記事の末尾にあります。

多くのプロジェクトチームは、Copilot と Teams を一日中開いたまま、すでに Microsoft 365 で作業しています。Catenda AI Connectは、Catenda Hubのmodel、ドキュメント、トピックを同じ場所に持ち込みます。プロジェクトに関する質問は、Microsoft 365 Copilot または Teams で自然な言葉で入力すると、ライブのプロジェクトデータから回答が得られます。

## 1. **概要**

Microsoft 365では、Catenda AI Connectはエージェントを通じてユーザーに提供されます。組織はこのエージェントを一度Copilot Studioで作成し、承認した上で、Microsoft 365 Copilot、Teams、またはその両方で利用可能にします。チームメンバーは、組織が提供する他のエージェントの中から、Catendaコネクタを使ったエージェントを見つけられます。

Microsoft 365 Copilotのエージェント一覧では、このようなエージェント（ここでは「Catenda」という名前）が次のように表示されます：

![Microsoft 365 Copilotのエージェントメニューに表示されたCatendaエージェント](https://catenda.github.io/help-center-ops/images/dvhm7pka/01-what-it-is.png)

この接続にはMCP（Model Context Protocol）を使用します。これは、AIアプリを他のシステムに接続するためのオープンな標準です。[Catenda AI Connectについて](https://support.catenda.com/ja/articles/17778695-catenda-ai-connectについて) では、製品全体について説明しています。

## 2. **チームでの用途**

### 2.1 **質問**

質問への回答は、ライブのプロジェクトデータに基づき、ソースを示した上で、Teams または Copilot のチャット内に直接表示されます。例:

```
プロジェクトで期限を過ぎているものは何ですか？また、担当者は誰ですか？
```

### 2.2 **確認**

トピック、model、ドキュメントは、プロジェクトの要件に照らして確認されます。納品物やその他のタスクに関連する場合もあります。例:

```
最新の納品物を当社の命名規則に照らして確認し、不合格の項目を一覧にしてください。
```

### 2.3 **委任**

組織がエージェントによる変更を許可している場合、定型的な作業は、担当者が承認する下書きとして実行されます。例:

```
これらの議事録の各アクションアイテムごとにトピックを作成してください。
```

## 3. **組織での設定**

Catendaコネクタを使用するエージェントは、役割の異なる二名によって一元的に設定されます。組織は複数のエージェントを設定でき、それぞれ Catenda Hub 内で異なる操作を許可し、異なるユーザーに提供できます。

### 3.1 **要件**

組織にはMicrosoft 365 BusinessまたはEnterpriseのサブスクリプションが必要です。エージェントを作成する担当者には、Copilot Studioのライセンスまたは試用版も必要です。エージェントを利用するユーザーには、これらの追加ライセンスは不要です。サブスクリプションとCopilot Studioのライセンスは、Microsoft 365管理センターの**Billing** > **Purchase services**から、またはMicrosoftパートナー経由で購入します。

### 3.2 **エージェントビルダー**

エージェントビルダーは、Copilot Studioでエージェントを作成し、Catendaコネクタを追加して、組織のカタログに申請します。Catendaの接続はCopilot Studioでカスタムコネクタとして提供されるため、組織のデータポリシーでカスタムコネクタを許可する必要があります。Power Appsでは、このコネクタを、エージェントの利用が承認された特定のユーザー、グループ、または組織全体と共有します。エージェントは、組織が選択した言語モデルで実行できます。組織が有効にしている場合はAnthropicモデルも含まれます。

Copilot Studioのエージェントページは次のようになります:

![新しいエージェントボタンが表示されたCopilot Studioのエージェントページ](https://catenda.github.io/help-center-ops/images/dvhm7pka/01-agent-builder.png)

### 3.3 **Microsoft 365管理者**

Microsoft 365管理者は、誰かが閲覧する前にエージェントを承認します。また、誰がインストールできるかを決定します。組織内の全員、または特定のチームのみを指定できます。後から別のチームにエージェントを提供する場合も、再作成は不要です。

## 4. **プロジェクトデータの管理**

各メンバーは、初めてエージェントを使用する際に自身のCatendaアカウントでサインインします。エージェントは、そのユーザーがCatenda Hubで持つアクセス権のみで動作し、プロジェクトの権限はそのまま適用されます。

組織は、エージェントが実行できる操作の種類を決定できます。例えば、プロジェクトデータの読み取り、トピックの作成や変更などです。機能ごとにアクセスを設定することもできます。例えば、エージェントがトピックを作成できるが、それ以外は読み取りのみとすることが可能です。また、エージェントが各操作の前にユーザーに確認するように設定することもでき、書き込まれる内容を担当者が管理できます。

## 5. **はじめに**

Catenda AI Connectは早期アクセス版として提供されています。

Catenda AI Connectは、Catenda Hubでプロジェクトを所有する組織だけのものではありません。他の組織のプロジェクトに招待された組織も、Catenda AI Connectを利用できます。そのような組織は、自らプロジェクトを所有している必要はありません。Catenda AI Connectは、二種類のプロジェクトで機能します。一つ目は、組織が自ら運営するプロジェクトです。二つ目は、組織が招待されているプロジェクトで、そのプロジェクトを運営する組織がCatenda AI Connectの利用を許可している場合です。組織がプロジェクトでCatenda AI Connectを許可しても、招待された全員が利用できるとは限りません。各個人の所属組織が、プロジェクトでのAI利用を禁止するポリシーを持っている場合があります。[Catenda AI Connectとプロジェクトアクセス](https://support.catenda.com/ja/articles/17778745-catenda-ai-connectとプロジェクトアクセス)では、この点について詳しく説明しています。

Catenda AI Connectを利用開始するには、Catendaの営業担当者にお問い合わせください：[https://catenda.com/get-started](https://catenda.com/get-started) または [sales@catenda.com](mailto:sales@catenda.com)。
