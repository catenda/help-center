# 組織とプロジェクトのセットアップ

Catendaで積極的な建設プロジェクトを開始する場合、新しい組織をCatendaの担当者が手動で作成することができます。プロジェクト作成へのアクセス権を持つユーザーは、このプラットフォーム組織内で独自のプロジェクトを作成できますが、アクセス権を持たないユーザーの場合はCatendaの担当者がプラットフォーム組織内にプロジェクトを作成できます。構造的な観点から、プロジェクトはさまざまな方法でプラットフォーム内にグループ化され、異なる運用ニーズに対応できます。たとえば、企業はすべてのプロジェクトのコンテナとして単一のプラットフォーム組織を使用することもできますし、複数の異なるプラットフォーム組織にプロジェクトを分散させることもできます。

本記事で説明されている構成は説明目的で提供されており、アカウントの特定の技術セットアップと条件に従うものです。これらの組織構造の可用性と機能的制限は、サービス契約の特定の条件によって管理されます。

## 1. **個別プロジェクト割り当て**

### 1.1 **プロジェクト割り当て**

プロジェクト作成へのアクセス権を持たないユーザーは、Catendaの担当者に連絡してプロジェクトの作成を依頼する必要があります。新しい機能をテストするか、すべてのユーザーが利用できない場合、期間限定のプロジェクトを作成して、組織所有者が機能をプロジェクトに対して有効にするかどうかを評価できるようにすることがよくあります。

### 1.2 **プロジェクトアクセス**

プロジェクト契約がキャンセルされた場合、キャンセル通知期間に従ってプロジェクトの有効期限が設定されます。プロジェクトのアクティブな期間が終了した後、またはプロジェクトの有効期限が切れた後、Catendaはプロジェクト情報を保持または保存する義務を負いません。

組織の構成をアクティブな作業に最適化するために、アクティブではなくなったプロジェクトは所有者によって削除される可能性があります。ユーザーは、プロジェクトが削除される前に、重要なデータが自身のストレージソリューションで保護されていることを確認することをお勧めします。プロジェクトのアクティブな期間が終了した後、Catendaサーバーで情報を保持または保存する義務はありません。有効期限前に必要と判断されるデータエクスポートまたはバックアップを管理することは、組織またはプロジェクト所有者の責任です。プロジェクトが有効期限に達した場合、または削除された場合、プロジェクト情報はサーバーに残ることが保証されなくなります。[ここ](https://support.catenda.com/en/articles/7946690-exporting-all-project-data)をクリックして、すべてのプロジェクト情報のエクスポートについて詳しく読むことができます。

### 1.3 **データ管理**

個別プロジェクト割り当てを使用する構成の場合、プラットフォーム上でアクティブではなくなったプロジェクトを維持するリクエストは、ケースバイケースで評価されます。Catenda担当者に連絡して、終了したプロジェクトまたは保留中だが参照用に保持することを目的としたプロジェクトのステータスを確認することができます。

## 2. **ボリュームベースのプロジェクト割り当て**

### 2.1 **プロジェクト割り当て**

アクティブなコラボレーションに従事している企業の場合、プラットフォーム組織はプロジェクト管理のための中央コンテナとして機能します。これらのコンテナの主な用途は、アクティブな製造および建設ワークフローを容易にすることです。

プラットフォーム組織の特定の構成に応じて、プロジェクト作成は2つの方法で管理されます：

**セルフサービス作成**適切な権限を持つユーザーは、アクティブなワークフローを容易にするために、プラットフォーム組織内で直接プロジェクトを作成できる機能を持つ場合があります。

**支援された作成**プラットフォーム組織がユーザー作成への直接アクセスなしで構成されている場合、Catendaの人員は会社に代わってプロジェクトを確立するのを支援する場合があります。これにより、その特定のコンテナに対してセルフサービスオプションが有効になっていない場合でも、アクティブな建設作業を続行できるようになります。

**セカンダリ構成**さらに、特定の構成は、新しい機能のテストや内部トレーニングなどのセカンダリ目的のために確立できます。これらのスペースは通常、主要な建設活動とは異なり、その特定のアカウント設定の機能的な境界に従います。

### 2.2 **プロジェクトアクセス**

組織の構成に応じて、所有者は異なる組織タイプ間のプロジェクトアクセシビリティと遷移を管理できる機能を持つ場合があります。組織の構成内でアクティブなワークスペースを最適化するために、主要なワークフローが終了したプロジェクトは削除される可能性があります。プロジェクトが削除された後、プロジェクト情報がサーバーに残ることを保証することはできなくなります。プロジェクトを削除する前に、データを顧客のストレージソリューションにバックアップできます。[ここ](https://support.catenda.com/en/articles/7946690-exporting-all-project-data)をクリックして、すべてのプロジェクト情報のエクスポートについて詳しく読むことができます。

### 2.3 **データ管理**

認可されたボリュームベースのセットアップ内では、プロジェクトを低アクティビティレベルを想定した組織構成に遷移させることができます。これにより、継続的なデータ参照と特定のデータ取得やマイナーな更新などの不定期なメンテナンスタスクが可能になり、プライマリ組織を高強度コラボレーション向けに最適化された状態に保つことができます。これらの遷移の可用性と機能的制限は、アカウント設定の特定の条件に従うものです。
