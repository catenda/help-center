# すべてのプロジェクトデータをエクスポートする

> Catenda Hubのプロジェクトデータ、ドキュメント、model、およびトピックのエクスポート方法の概要。利用可能なオプションには、Desktop Connectorの同期、PDF/Aレポート作成、アクセス許可監査、およびAWS S3またはAzure Blobストレージへの自動クラウドバックアップが含まれます

Catenda Hubは、日々のダウンロードから自動エンタープライズアーカイブまで、様々なプロジェクト要件に合わせたフレキシブルなエクスポート方法を提供します。特定のプロジェクト要件に応じて、Desktop Connectorを使用して大規模なフォルダ構造を同期し、Reports Pageを介してカスタムドキュメント配送チェックリストおよびPDF/Aアーカイブを生成し、またはプロジェクトアクセス許可を文書化して監査証跡を作成することが可能です。継続的なクラウド間バックアップが必要な組織の場合、Catenda Data Exportはおよため自動転送を直接AWS S3またはAzure Blobストレージに提供します。

このアーティクルで説明するトピックは以下の通りです：

## 1. **エクスポート理由**

プロジェクトオーナーおよびプロジェクト参加者は、プロジェクトのライフサイクル中およびその後、プロジェクトドキュメントのローカルコピーを保持する必要があることがよくあります。

### 1.1 **データ提出とフェーズ変更**

プロジェクトデータは、様々なプロジェクトマイルストーンで必要とされることがあります：

**フェーズ変更**計画、設計、および建設の間の遷移には、特にプロジェクトが保留または新しい関係者に引き継がれる場合、データスナップショットの抽出が必要になることがよくあります。

**政府への問い合わせ**プロジェクト中またはプロジェクト完了時に、公式な当局への提出が頻繁に必要とされます。

**入札**入札用のドキュメント提出パッケージの準備。

### 1.2 **独立したデータ保持およびアクセス保護**

エクスポートはプロジェクト完了に限定されません。メインプロジェクトデータを所有しないプロジェクトメンバーは、自分の作業への継続的なアクセスを確保するために、独自のコピーを必要とすることがよくあります。

プロジェクトメンバーは、プロジェクトアクセスがいつ終了するかについて常に事前に通知されるわけではなく、アクセスが予想より早く取り消される場合があります。警告なしにアクセスが失われる可能性があるため、**Catenda Data Export**または**Catenda Desktop Connector**などの**スケジュール設定された定期的なエクスポート**を構成することが重要です。これらの定期的なツールは、プロジェクトメンバーがアクセスを失う前の最後のスケジュール実行までのローカルまたはクラウドバックアップを保持することを確保します。

### 1.3 **データアーカイブおよびコンプライアンス**

規制および業界標準は、責任ある関係者が長期間(多くの場合、数年から数十年にわたる)プロジェクトレコードを保存することを頻繁に義務付けています。システムドキュメント、製品レコード、およびコンプライアンスファイルは、会社のサーバーまたは指定されたリポジトリに保存する必要がある場合があります。

### 1.4 **プロジェクト終了**

アクティブなプロジェクトが完了するか、ライセンス期間が終了する場合、Catendaはプロジェクトデータを安全に保存された状態に保ちます。プロジェクトアクセスが終了した場合でも、データはCatendaサーバー上で最大3年間回復可能です。

### 1.5 **フローズンアーカイブオプション**

アーカイブオプションにより、プロジェクトは選定されたメンバーのためにアクセス可能な読み取り専用リポジトリとして凍結された状態で残ります。

## 2. **標準エクスポートオプション**

これらのビルトインエクスポートツールは、標準インターフェース内で、すべての認可されたプロジェクト参加者に直接利用可能です。

### 2.1 **modelのエクスポート**

Catenda内のすべてのモデルはドキュメントセクション内のドキュメントにリンクされているため、標準ドキュメントエクスポート機能もモデルに適用されます。さらに、モデル用の専用エクスポートオプションが利用可能です：

**選択したモデルのダウンロード** [モデルページ](https://support.catenda.com/en/articles/4670286-models-page)で1つ以上のモデルを選択し、ダウンロードアクションを使用して最新版を抽出します。

**個別revisionダウンロード** [modelsページ](https://support.catenda.com/en/articles/4670286-models-page)でmodelを選定し、右情報パネルの各revisionの隣のダウンロードボタンを使用します。これにより、完全な[modelコンテンツページ](https://support.catenda.com/en/articles/4670270-model-contents-page)をロードする必要なく、特定のrevisionを直接ダウンロードする効率的な方法が提供されます。別の方法として、individual revisionsはmodelのコンテンツページから直接ダウンロードすることもできます。

**高度なmodelエクスポート** [modelエクスポートページ](https://support.catenda.com/en/articles/4670280-model-export-page)にアクセスして、複数のmodel全体で選定されたrevisionをダウンロード可能なZIPファイルにパッケージ化します。この方法には、タグ、ユーザー定義プロパティ、またはライブラリ情報をベイク・インすることにより、エクスポートされたmodelファイルを拡張するための高度なオプションが含まれています。

### 2.2 **トピックのエクスポート (3つの方法)**

トピックデータは、情報がどのように表示、分析、または保存されるかに応じて、[トピックの交換](https://support.catenda.com/en/articles/4670289-exchange-topics)を介して3つの主要フォーマットを使用して抽出できます：

**BCF (BIM Collaboration Format)**トピック作成タイムスタンプを含め、公式BCF仕様に厳格に準拠するトピック情報をキャプチャおよび転送するために設計されたオープンスタンダード。このフォーマットは、幅広いクロスプラットフォーム相互運用性を保証し、他のBCF互換ソフトウェアでシームレスにトピックデータを再度開く、編集、または交換するのに理想的です。直接ファイルプレビューが必要な一般的な長期ドキュメントリポジトリの場合、通常PDFまたはExcelフォーマットが推奨されます。

**Excel**トピックパラメータをスプレッドシートフォーマットにエクスポートして、フィルタリング、ソート、およびデータ操作を行います。このフォーマットは、データの選定およびコピーに理想的な構造化された行と列を提供し、Excelファイルはほとんどのアーカイブプラットフォーム内で簡単にプレビューできます。アーカイブ目的では、より多くの情報が含まれているため、一般的にPDFエクスポートがExcelより推奨されます。

**PDF**標準PDFフォーマット (v1.4)でクリーンで読みやすいサマリーレポートを生成し、特別なソフトウェアなしでアクセス可能です ([トピックをPDFにエクスポート](https://support.catenda.com/en/articles/9784934-exporting-topics-to-pdf)参照)。標準PDFエクスポートには、公式当局レポートおよびアーカイブ用の統合ダウンロードタイムスタンプが含まれ、Excelエクスポートより多くの情報を提供します。基本エクスポートは標準PDF (v1.4)ファイルを生成し、多くのアーカイブシステムはアップロード時に自動的にPDF/Aに変換して長期プレビューを行いますが、ネイティブPDF/A-1、PDF/A-2、およびPDF/A-3フォーマットへの直接エクスポートはオプトイン[Reports Page](https://support.catenda.com/en/articles/12303098-reports-page)を介して利用可能です。

### 2.3 **ドキュメントおよびコレクションのエクスポート**

**バッチおよびフォルダダウンロード**個別のフォルダ、特定のドキュメントバッチ、またはすべての表示テーブルアイテムを一度に選定して、ダウンロード可能なZIPアーカイブを生成します。大規模なデータセットで作業する場合、スムーズな転送のため、特定のサブフォルダまたは対象ファイルグループを選定して管理可能なバッチでダウンロードすることを推奨します。

- **公開タブ**
  各選定ドキュメントの最新公開revisionを抽出します。
- **ワークスペースタブ**
  各選定ドキュメントの最新共有revision (「共有revisionの表示」許可が必須)を抽出します。レガシードラフトrevisionはZIPアーカイブにバッチダウンロードすることはできず、個別にダウンロードされることに注意してください。

**個別revisionダウンロード** [ドキュメントページ](https://support.catenda.com/en/articles/8204673-documents-page)でドキュメントを選定し、右情報メニューにリストされた各revisionの隣のダウンロードボタンをクリックします。ドキュメントプレビューページをロードする必要がないため、個別または過去のrevisionをダウンロードするより簡単な方法です。テーブル内の別のドキュメントを選定し、新しいプレビューページを開く必要なく右メニューのrevisionをダウンロードできます。

**公開コレクション** [コレクション](https://support.catenda.com/en/articles/6344318-collections-page)を使用して、選定されたドキュメントサブセット用の公開リンクを作成し、Catendaアカウントを要求せずに外部パーティがファイルをダウンロードできるようにします。公開revisionのみがコレクションに追加できることに注意してください。

**削除されたファイル**ドキュメント検索バーで「削除済み」を検索して、以前に削除されたドキュメントを見つけてエクスポートします。このフィルタは言語固有であり、現在の言語設定の「削除済み」という用語に対応することに注意してください。

### 2.4 **Desktop connector (自動ローカルバックアップ)**

[Catenda Desktop Connector](https://support.catenda.com/en/articles/8358861-catenda-desktop-connector)は、新しいドキュメントrevisionを定期的にダウンロードしてローカルドライブに直接保存するバックグラウンド同期を有効にします。バッチウェブエクスポートと異なり、ダウンロードされたドキュメントはシステムに直接未圧縮ファイルとして到着し、手動アーカイブ抽出を必要としません。

**スケジュール設定および即時バックアップ**タスクは定期的な間隔で自動実行されるようにスケジュール設定することも、オンデマンドで実行することもでき、プロジェクトメンバーがプロジェクトアクセスが予期せず取り消された場合でもドキュメントの最新ローカルコピーを保持することを確保します。

**直接API転送**ブラウザメモリの制限またはオーバーヘッドなしで直接API接続を活用することで、ウェブブラウザダウンロードより有意に大規模なデータセットをより高速に転送します。

**階層オプション**完全な階層がそのまま保持された選定フォルダ構造をダウンロードするか、個別に選定されたファイルを指定されたローカルフォルダにフラットリストとして直接抽出します。

### 2.5 **メンバーアクセスおよびアクティビティログ**

**トピックボード** 2つの利用可能なビューを使用してボードアクセス許可を文書化します：

- **ユーザーごとのアクセスビュー**
  トピックボードまたは選定されたトピックの右情報メニューから個別ユーザーアクセスレベルを直接表示します。
  ​_必須アクセス:_ トピックボードへの読み取りアクセス
- **フルチーム設定**
  トピックボードアクセス設定内のチームレベルアクセス許可設定全体のスクリーンショットをキャプチャします。
  ​_必須アクセス:_ トピックボードまたはプロジェクト管理者への完全アクセス

**ドキュメント&Model アクセス** [アクセス概要](https://support.catenda.com/en/articles/6660820-document-access-overview-page)をエクスポートして、メンバーおよびチームのアクセス許可を記録します。必須アクセス: プロジェクト管理者。Catenda内のすべてのmodelはドキュメントセクション内のドキュメントにリンクされているため、modelのアクセス許可は基盤となるドキュメントアクセス許可により管理され、同じドキュメントアクセス概要またはアクセス許可メニューを使用して記録されます。

**ドキュメント&Model revision アクセス** [ドキュメント revisionの右メニュー](https://support.catenda.com/en/articles/8302244-right-menu-of-a-revision-revision-info)からアクセス許可を表示し、必要に応じてスクリーンショットをキャプチャします。

**プロジェクト全体のアクション権限** [プロジェクト設定ページ](https://support.catenda.com/en/articles/4670273-project-settings-page)にプロジェクト全体のアクセス許可を文書化します（トピックボード作成、新しいメンバー招待、ドキュメントステータス設定、モデル作成または削除など）。2つの利用可能なビューを使用します：

- **ユーザーごとのアクセスビュー**
  プロジェクトメンバーは、アクセス制御下の各メニューを展開して、各アクションを実行するアクセス許可を持つ個別ユーザーを確認できます。
- **フル設定**
  管理者はアクセス編集ダイアログを開いて、チームレベルアクセス許可設定を表示および管理できます。
  ​_必須アクセス:_ プロジェクト管理者

**ユーザープロファイル＆メンバー詳細**プロジェクトメンバーおよびチームに関する情報は、抽出または文書化するために利用可能で、以下を含みます：

- ユーザー名およびメールアドレス ([カスタムメンバー情報](https://www.google.com/search?q=https://support.catenda.com/en/articles/11769670-custom-member-information%23h_c15463ee3f)参照)。
- チームメンバーシップ、割り当てられたトピック、アップロードされたmodelrevision、およびアクセス許可設定 ([メンバーページ](https://www.google.com/search?q=https://support.catenda.com/en/articles/4670291-members-page)または[チームページ](https://www.google.com/search?q=https://support.catenda.com/en/articles/4670291-members-page)経由でキャプチャ)。

### 2.6 **通知**

[プロジェクト通知ページ](https://support.catenda.com/en/articles/4670295-project-notifications-page)からのスクリーンショット経由で通知ページをキャプチャし、[制限フィルター](https://support.catenda.com/en/articles/8304417-filtering-on-the-notifications-page)を使用してページあたりの表示可能なアイテムを最大化します。

[プロジェクト特定通知設定](https://support.catenda.com/en/articles/4670262-project-specific-notification-settings)を有効にして検索可能な通知ログを維持するための電子メールサマリーで専用管理アカウントを設定します。

### 2.7 **Reports Page (オプトイン機能)**

**オプトイン活性化** Reports pageはオプトイン機能で、進行中のプロジェクトに対して有効化をリクエストできます。このツール使用に追加支払い必須ではありませんが、プロジェクトオーナーはプロジェクトで有効化に同意する必要があります。これは、多くのプロジェクトではデフォルトでアクティブではないということを意味します。Reports有効化されたテンプレートプロジェクトから作成された新しいプロジェクトはこの機能が自動的に有効化されないことに注意してください。

**テンプレートベース管理**有効化時、プロジェクト管理者は[レポートテンプレートページ](https://support.catenda.com/en/articles/12380837-report-templates-page)を使用してカスタムレポートテンプレートを設定し、選定されたドキュメントまたはトピックのための書式設定エクスポートを生成できます。

**ドキュメントレポート**ドキュメント名、revision名、最新revision番号、ステータス、カスタムフィールド、作成者、アップローダー、作成/アップロードタイムスタンプを含むすべての選定ファイルのドキュメントメタデータおよびrevision詳細をエクスポートします。

- **主要ユースケース**
  コレクション添付用の公式ドキュメント配送チェックリストを生成するか、データ分析用の構造化ドキュメントリストをコンパイルするのに理想的です。
- **Model メタデータ&属性**
  実際のドキュメントファイルコンテンツは含まれていませんが、modelメタデータはmodelがドキュメントセクションへのリンクを保持するので、ドキュメントレポートを介してエクスポートできます。テンプレート内のカスタムスクリプトはまた、ドキュメント名からファイルタイプを抽出するなど追加の属性を導出するために使用できます。

**トピックレポート**トピックヘッダー全体およびコメント、埋め込みコメント画像を含む完全なトピック本文詳細をエクスポートします。

**利用可能なエクスポートフォーマット**テンプレートから作成されたレポートは、ワークフロー要件に応じて複数のフォーマットにエクスポートできます：

- **PDF / PDF/A**
  クリーンな書式設定レポートを生成し、ネイティブPDF/Aコンプライアンス (PDF/A-1、PDF/A-2、およびPDF/A-3)を直接サポートして、厳格な長期アーカイブおよび公式法定基準を満たします。
- **Excel**
  構造化表形式データをスプレッドシート行と列にエクスポートし、データ操作および外部分析に理想的です。
- **追加フォーマット**
  PDFおよびExcel以外の幅広い追加ファイルフォーマットもエクスポート用にサポートされています。完全な概要は[Reports page](https://support.catenda.com/en/articles/12303098-reports-page)アーティクルで見つけることができます。

**一元化されたストレージ**生成されたレポートはレポートテーブル内に直接リストされ、簡単な管理のためにメインドキュメントテーブルに自動的に統合されます。

## 3. **Catenda Data Export**

標準ユーザー駆動ダウンロードとは異なり、Catenda Data Exportは、プロジェクトデータを組織のクラウドストレージに直接シームレスに転送するために設計された自動自己サービスソリューションです。組織がこの機能の有効化に関心を持つ場合、[sales@catenda.com](mailto:sales@catenda.com)で営業に連絡できます。有効化後、クラウド環境間で直接自動バックアップを提供し、カスタムスクリプト、ブラウザメモリの制約、ローカルドライブストレージ制限、およびネットワーク中断を自動チェックサム検証によりバイパスする必要がありません。

### 3.1 **組織ロール&アクセス許可**

Catenda Data Exportの設定および管理には、**Organization Administrator（組織管理者）**が必須です。組織所有者（管理権が単一の組織に限定される）または標準プロジェクトメンバーと異なり、Organization Administratorは、上位アカウントに属するすべての組織にわたって昇格されたアクセス権を保持します。この固有のロールは、自動クラウドエクスポート設定および管理に必要なクロスオーガニゼーション可視性および権限を付与します。

### 3.2 **設定ステップ**

自動データエクスポートの設定には、4つの主要ステップが含まれます：

1. **宛先を選択**
   Amazon Web Services (AWS) S3またはMicrosoft Azure Blobストレージのクラウドストレージプロバイダを選択し、認証を設定します。
1. **スコープ&データフォーマットを定義**
   - **データ型**
     ドキュメント、model、およびトピックをエクスポート。
     トピックデータは転送中に自動的に読み取り可能なPDFサマリーレポートまたは標準BCFファイルに変換できます。
   - **プロジェクト選択**
     すべてのプロジェクトを選択するか、特定のプロジェクトを手動で選択するか、プロジェクト名パターン (glob または正規表現 / regex)を使用して動的マッチングルールを設定して、作成されるので新しいプロジェクトを自動的に含めます。
1. **エクスポートモードを選択**
   - **継続的モード**
     毎日のスケジュールでデータを自動的に配信。
     この定期設定は、プロジェクトアクセスが予期せず終了する場合に、所有者以外のプロジェクトメンバーが最後の毎日実行までの更新されたバックアップを保持することを確保します。
   - **スナップショットモード**
     特定のマイルストーンまたはプロジェクト引き継ぎで完全なデータセットをエクスポートするための1回限りの実行を実行します。
1. **デプロイ**
   Creat選択によるエクスポート設定を最終化および有効化します。

### 3.3 **抽出コンテンツ&整合性検証**

**メタデータ&カスタムフィールド**ドキュメントおよびトピックに関連付けられたカスタムフィールドは、構造化JSONファイルとしてプライマリファイルと並行してエクスポートされ、手動レポート生成なしで完全な属性保持を確保します。

**整合性検証**エクスポート実行ごとにチェックサムファイルを生成して、エクスポートされたファイルがCatenda Hubのソースデータと一致し、ネットワーク損失なしで完全に転送されたことを検証します。

**整理された階層**エクスポートされたファイルは、日付、プロジェクト名、およびCatenda Hubに保持された正確なフォルダ階層に従って整理されたフォルダに自動的に構造化されます。
