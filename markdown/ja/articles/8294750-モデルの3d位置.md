# モデルの3D位置

## 1. **同じ座標でのエクスポート**

オーサリングプラットフォームでは、異なる座標でエクスポートできます。すべての座標はCatenda Hubで正常に機能します。プロジェクト内の全員が同じ座標系を使用することをお勧めします。これにより、オブジェクトが互いに遠く離れることがなく、ユーザーは見えるオブジェクトと見えないオブジェクト(実際には非常に遠く離れているだけ)があることを疑問に思いません。

## 2. **原点から遠いオブジェクト**

他のオーサリングプラットフォームと比較して、Catenda hubは0から遠いオブジェクトでも精度の問題がありません。IFCファイルで指定されたモデルの位置は、3D内でモデルが存在する場所を決定するために使用されます。シーン(3Dビューアに読み込まれる領域のサイズ)は、その中に含まれるオブジェクトと同じ大きさであり、原点(0,0,0)を含む必要はありません。これにより、オブジェクトと原点の関係でどれだけ遠いかを計算することなく、オブジェクトに簡単にズームインできます。

## 3. **他のオブジェクトから遠いオブジェクト**

互いに10000 km以上離れたオブジェクトがある場合、シーンが非常に大きくなるため問題が発生する可能性があります。水平クリッピング平面を作成すると、シーン全体がクリップされ、移動すると敏感になります。モデルが誤った座標でインポートされ、非常に遠く離れてしまった場合は、変換したい場合があります。モデルは単独でも正常に機能しますが、非常に遠く離れた他のモデルと一緒に使用すると、問題が発生する可能性があります。

## 4. **モデルの位置の変換**

3Dで読み込まれている場合、モデル概要ページでモデルの3D位置を変換することは可能です。これにより、Catenda Hubにインポート後、3D内でモデルを移動できます。この移動はCatenda Hub内でのみ表示されます。IFCをダウンロードすると、元の位置に戻ります。この方法は、正しい位置を持つifcファイルを待つ間、一時的にモデルを変換することのみお勧めします。これは、2Dビューアセクション、クエリ、およびissueスナップショットなど、変換されたモデルでは一部の機能が正常に機能しないためです。測定値は影響を受けず、モデルが正しい場所に移動された場合は正確になります。この方法の詳細については、[こちら](https://support.catenda.com/en/articles/4670270-model-overview-page#h_c10dbce6c8)をご覧ください
