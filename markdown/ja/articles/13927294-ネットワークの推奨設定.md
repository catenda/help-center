# ネットワークの推奨設定

システムが接続されているネットワークの構成は、Catendaで経験されるパフォーマンスに影響を与える可能性があります。

## 1. **ネットワーク速度**

ネットワークの品質を制御して、ダウンロードとアップロード間の比率が1:10以上になるようにしてください。

![](https://raw.githubusercontent.com/catenda/help-center/main/images/4f22q5zf/01-network-speed.png)

(このネットワークテストは一例であり、実際の要件ではありません)

## 2. **プロキシとファイアウォール:**

ファイアウォール、プロキシ、またはその他の中間装置の背後からCatenda Hubにアクセスするユーザーは、アプリケーションが正常に機能するために、以下のドメインとポートへのアクセスが必要です。

### 2.1 **ドメイン:**

(`*`はDNSワイルドカードを意味し、`.`はドメインレベルの区切り文字です。以下を正規表現として扱わないでください)。

- Catendaドメイン：
  - `catenda.com`
  - `*.catenda.com`
    - `webviewer.catenda.com`
      このサブドメインは、ドキュメントプレビューページでドキュメントのプレビューを表示するために、ファイアウォールで許可される必要があります。
  - `*.*.catenda.com`

この新しいドメイン名の使用をお勧めします。`*.*.*.catenda.com`などのサブドメインが増えても問題が発生しないはずですが、発生した場合は`catenda.com`からのすべてを許可する方が簡単かもしれません

**保守されているドメイン**以下のドメインは予見可能な将来において保守されますが、技術文献では参照されません。

## 3. **ポート設定**

### 3.1 **ポート80**

このポートはオプションですが、最適なブラウザ内ユーザーエクスペリエンスのために推奨されます。プロトコル: TCP (hub.catenda.comと[www.hub.catenda.com](http://www.hub.catenda.com)のみ) ポート80でリクエストを試行するクライアントは、ポート443で同等の暗号化されたコールを実行するようにリダイレクトされます。

### 3.2 **ポート443**

プロトコル: TCP + UDP すべてのCatenda Hubトラフィックはこのポート上でTLS暗号化されています。UDPはオプションですが、互換性のあるブラウザーおよび他のクライアントがHTTP/3 (以前のQUIC)などのHTTPプロトコルの進歩を活用できるようにするため、最適なユーザーエクスペリエンスのために推奨されます。これはプラットフォーム全体にロールアウト中です。
